# Общая конфигурация

Все конфигурационные файлы October CMS располагаются в каталоге `config`. Каждый параметр конфигурации снабжён встроенной документацией.

## Конфигурация окружения

Многие параметры October CMS можно задать с помощью переменных окружения. Их можно определить на уровне сервера или настроить для [виртуального хоста веб-приложения](https://httpd.apache.org/docs/2.4/env.html).

::: aside
October CMS использует [библиотеку DotEnv](https://github.com/vlucas/phpdotenv), которая упрощает работу с переменными окружения.
:::

Переменные окружения также можно определить в файле `.env`, который скрипт установки автоматически создаёт в корне проекта. В новой установке October CMS в корневом каталоге есть файл `.env.example` с типовыми значениями для локального окружения.

Например, подключение к базе данных можно настроить с помощью следующих переменных:

```ini
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=database
DB_USERNAME=root
DB_PASSWORD=
```

Любую переменную в файле `.env` можно переопределить внешними переменными окружения, заданными на уровне сервера или виртуального хоста.

Значения конфигурации загружаются в следующем порядке:

1. переменные окружения системы
2. переменные из файла .env
3. значения из PHP-файлов конфигурации.

::: warning
Никогда не добавляйте файл `.env` в систему контроля версий. Это создаёт риск безопасности, если злоумышленник получит доступ к репозиторию.
:::

### Конфигурационные файлы для конкретного окружения

Если нужно загрузить файл конфигурации в зависимости от текущего окружения приложения, например, стенда или продакшна, используйте переменную `APP_ENV` на уровне сервера. Пример конфигурации Apache:

```text
SetEnv APP_ENV "staging"
```

Когда переменная `APP_ENV` определена, платформа пытается загрузить файл .env с суффиксом, соответствующим названию окружения, например **.env.staging**. Если файл отсутствует, ошибка не возникнет. Когда одновременно существуют файлы **.env.staging** и **.env**, последний полностью игнорируется.

При использовании кэшированной или [оптимизированной конфигурации](./web-server-config.md) значение `APP_CONFIG_CACHE` можно указать в файле **.env**, чтобы изменить путь к файлу кэша. Это гарантирует, что каждое окружение получит собственные кэшированные значения конфигурации.

```ini
APP_CONFIG_CACHE=storage/framework/config-staging.php
```

## Конфигурация для продакшна

В производственных окружениях следует обязательно настроить несколько важных параметров конфигурации.

### Режим отладки

Параметр `debug` находится в файле `config/app.php` и должен быть отключён на боевом сервере. По умолчанию значение загружается из переменной окружения `APP_DEBUG`. Сразу после установки режим отладки включён в файле `.env`.

```ini
APP_DEBUG=false
```

Если режим отладки включён, при возникновении ошибок отображаются подробные сообщения, а также доступны другие инструменты отладки. Это полезно во время разработки, но на рабочем сайте его необходимо отключить, чтобы не раскрывать посетителям потенциально чувствительные данные.

Функции, доступные при включённом режиме отладки:

- [подробные сообщения об ошибках](../../cms/pages.md#error-page)
- при неудачной авторизации пользователя выводится точная причина
- [комбинированные ресурсы](../../markup/filter-theme.md) по умолчанию не минифицируются

### Защита от CSRF

October CMS предоставляет встроенный механизм защиты от [межсайтовой подделки запроса (CSRF)](https://owasp.org/www-community/attacks/csrf). Когда защита включена, October CMS сохраняет случайный токен в сессии пользователя. [Тег открытия формы](../../extend/services/html.md#opening-a-form) и [тег токена формы](../../extend/services/html.md#form-tokens) добавляют скрытое поле с этим значением в форму. Для всех запросов POST, PUT или DELETE платформа проверяет, совпадает ли отправленный токен с токеном в сессии.

Защита от CSRF включена по умолчанию. Параметр `enable_csrf_protection` находится в файле `config/system.php`. По умолчанию значение загружается из переменной окружения `ENABLE_CSRF`.

### Публичный каталог

В производственных окружениях рекомендуется использовать [публичный каталог](../setup/web-server-config.md), чтобы изолировать внутренние файлы от публичных. Это дополнительный уровень защиты, дополняющий [конфигурацию веб-сервера](../setup/web-server-config.md), которая открывает только индексный PHP-файл и статические ресурсы.

### Резервная тема

[Активная тема CMS](../../cms/themes/themes.md) обычно хранится в базе данных. На боевом сервере возможна ситуация, когда при сбое подключения к базе данных пользователю показывается демо-тема или общий экран ошибки. Чтобы этого избежать, задайте резервную тему в конфигурации файлов.

Резервная активная тема задаётся в файле `config/cms.php` и загружается из переменной окружения `ACTIVE_THEME`. Убедитесь, что здесь указана существующая тема, поскольку это значение будет использоваться при отсутствии базы данных.

```ini
ACTIVE_THEME=my-theme
```

### Отключение редактора

Одно из преимуществ October CMS заключается в возможности безопасно вносить изменения на сайте прямо в продакшне, например, быстро поправить HTML или добавить страницу. Это удобно для небольших проектов, однако в крупных системах может потребоваться строгий контроль изменений.

Чтобы запретить изменения на продакшне, можно отключить Редактор одним из следующих способов.

- загрузить только необходимые модули с помощью конфигурации `system.load_modules`
- не развёртывать файлы редактора из [каталога modules](./directory-structure.md)
- использовать [права доступа](../../extend/backend/permissions.md), чтобы закрыть доступ к редактору

::: tip
Также рекомендуется перевести каталоги [app и themes](./directory-structure.md) в режим только для чтения.
:::

В качестве альтернативы можно [включить безопасный режим](../setup/web-server-config.md), чтобы редактор оставался доступным в продакшне. Безопасный режим позволяет обновлять HTML, CSS и другие файлы, но блокирует изменения PHP-кода и потенциально небезопасные функции Twig.
