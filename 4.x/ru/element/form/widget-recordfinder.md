# Поле Record Finder

Виджет формы `recordfinder` выводит поле с данными связанной записи. При раскрытии поле открывает всплывающий список для поиска по большому числу записей. Поддерживаются только одиночные связи.

```yaml
user:
    label: User
    type: recordfinder
    list: ~/plugins/rainlab/user/models/user/columns.yaml
```

Поддерживаются и часто используются следующие [свойства поля](../form-fields.md).

Свойство | Описание
------------- | -------------
**label** | имя, отображаемое пользователю.
**default** | задаёт строковое значение по умолчанию, необязательное.
**comment** | размещает описательный комментарий под полем.
**keyFrom** | имя столбца в связи, используемое как ключ. Значение по умолчанию — `id`.
**nameFrom** | имя столбца в связи для отображения названия. Значение по умолчанию — `name`.
**descriptionFrom** | имя столбца в связи для отображения описания. Значение по умолчанию — `description`.
**title** | текст, отображаемый в заголовке всплывающего окна.
**list** | конфигурационный массив или ссылка на файл с определением столбцов списка.
**filter** | ссылка на файл определения областей фильтра, см. [фильтры списков бэкенда](../../extend/lists/filters.md).
**showSetup** | показывает кнопку настройки для конфигурации столбцов списка и количества записей на странице. Значение по умолчанию — `false`.
**structure** | включает доступный только для чтения структурированный список для выбора записей, см. [статью о сортировке записей](../../extend/lists/structures.md). Установите `false`, чтобы отключить. Иначе включается, если модель использует древовидный интерфейс.
**defaultSort** | задаёт столбец и направление сортировки по умолчанию при отсутствии пользовательских настроек. Поддерживает строку или массив с ключами `column` и `direction`. Для направления используйте `asc` (по возрастанию, по умолчанию) или `desc` (по убыванию).
**recordsPerPage** | количество записей на странице; используйте `0`, чтобы отключить пагинацию. Значение по умолчанию — `10`.
**conditions** | произвольное выражение WHERE, применяемое к запросу модели списка.
**modelScope** | применяет [область запроса модели](../../extend/database/model.md) к **связанной модели формы**. Можно указать метод модели или статический метод PHP (`Class::method`). Первым аргументом будет модель, к которой виджет привязывает значение, то есть родительская модель.
**searchMode** | задаёт стратегию поиска: по всем словам, любому слову или точной фразе. Доступные значения: `all`, `any`, `exact`. Значение по умолчанию — `all`.
**searchScope** | указывает [область запроса модели](../../extend/database/model.md), определённую в **связанной модели формы**, применяемую к поисковому запросу. Первым аргументом будет поисковый термин.
**useRelation** | признак использования имени поля как имени связи для прямого взаимодействия с родительской моделью. Значение по умолчанию — `true`. Отключите, чтобы возвращался только идентификатор выбранной модели.
**modelClass** | класс модели для вывода списка записей, когда `useRelation` имеет значение `false`.
**popupSize** | размер всплывающего окна селектора: `giant`, `huge`, `large`, `small`, `tiny` или `adaptive`. Значение по умолчанию — `huge`.
**inlineOptions** | отображает поле с кнопками рядом с выбранной записью. Отключите режим, если горизонтального пространства недостаточно. Значение по умолчанию — `true`.

Ограничить количество записей на странице можно свойством `recordsPerPage`.

```yaml
user:
    label: User
    type: recordfinder
    recordsPerPage: 10
```

Используйте свойство `title`, чтобы изменить заголовок формы управления.

```yaml
user:
    label: User
    type: recordfinder
    title: Find A User
```

После выбора записи отображаемые атрибуты можно определить через атрибуты модели с помощью свойств `nameFrom` и `descriptionFrom`.

```yaml
user:
    label: User
    type: recordfinder
    nameFrom: name
    descriptionFrom: email
```

Если обнаружена [структура модели](../../extend/lists/structures.md), список будет отображён в структурированном виде. Это можно явно отключить или включить свойством **structure**.

```yaml
user:
    label: User
    type: recordfinder
    structure: false
```

## Использование в Tailor

Когда поле `recordfinder` используется как [контентное поле Tailor](../../cms/tailor/content-fields.md), необходимо указать свойство `modelClass`, чтобы определить и найти связь модели.

```yaml
products:
    label: Products
    type: recordfinder
    modelClass: Acme\Test\Models\Product
    list: $/october/test/models/product/columns.yaml
```

Если `maxItems` равно **1**, связь определяется как `belongsTo`. В остальных случаях связь определяется как `belongsToMany`.

```yaml
products:
    label: Products
    type: recordfinder
    modelClass: Acme\Test\Models\Tag
    maxItems: 1
```

Свойство `inverse` можно установить в имя связи на связанной модели. Это изменит определение связи на `hasOne`, `hasMany` или `belongsToMany` в зависимости от параметра `maxItems` и типа связи связанной модели.

```yaml
tags:
    label: Tags
    type: recordfinder
    modelClass: Acme\Test\Models\Tag
    inverse: tags
```
