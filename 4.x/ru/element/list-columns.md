# Колонки списков (List Columns)

Колонки списков — это определения колонок, которые используют списки. Они применяются в следующих местах:

- [Поведение Backend List Controller](../extend/lists/list-controller.md)
- [Поведение Backend Relation Controller](../extend/forms/relation-controller.md)

Все колонки списков идентифицируются по своему свойству **type**.

```yaml
columns:
    mycolumn:
        type: number
        # ...
```

## Свойства колонки

Для каждой колонки можно указать следующие свойства (где применимо).

Property | Description
------------- | -------------
**label** | имя при отображении колонки списка пользователю.
**type** | определяет способ отображения колонки.
**default** | задаёт значение по умолчанию, если основное значение пустое.
**searchable** | включает колонку в результаты поиска списка. Значение по умолчанию: `false`.
**invisible** | определяет, скрыта ли колонка по умолчанию. Значение по умолчанию: `false`.
**sortable** | определяет, можно ли сортировать колонку. Значение по умолчанию: `true`.
**sortableDefault** | задаёт сортировку по умолчанию для колонки. Используйте только для одной сортируемой колонки. Поддерживаемые значения: `asc`, `desc`.
**clickable** | если указано `false`, отключает стандартное поведение при клике по колонке. Значение по умолчанию: `true`.
**select** | задаёт пользовательское выражение SQL select для получения значения. Если указано `relation`, относится к колонке в связанной таблице.
**valueFrom** | определяет атрибут модели как источник значения. Если указано `relation`, относится к атрибуту связи и выполняет eager loading.
**displayFrom** | определяет атрибут модели, используемый для отображения значения.
**relation** | задаёт имя связи модели как источник, используется с `select` или `valueFrom`.
**relationCount** | отображает количество связанных записей как значение колонки. Используется вместе с параметром `relation`. Значение по умолчанию: `false`.
**relationWith** | выполняет eager loading указанного определения связи в запросе списка. Полезно для ускорения вложенных выборок.
**cssClass** | назначает CSS‑класс контейнеру колонки.
**headCssClass** | назначает CSS‑класс контейнеру заголовка колонки.
**width** | задаёт ширину колонки в процентах (10%) или пикселях (50px). Может быть только одна колонка без ширины — она растягивается на доступное пространство.
**align** | задаёт выравнивание колонки. Возможные значения: `left`, `right`, `center`.
**permissions** | [разрешения](../extend/backend/permissions.md), которые должны быть у текущего пользователя бэкенда, чтобы колонка была доступна. Поддерживает строку с одним разрешением или массив, из которого требуется хотя бы одно разрешение.
**order** | числовой вес для определения порядка отображения; значение по умолчанию увеличивается на 100 для каждой колонки.
**after** | располагает колонку после существующей, используя порядок отображения (+1).
**before** | располагает колонку перед существующей, используя порядок отображения (−1).
**tooltip** | добавляет иконку с подсказкой рядом с меткой колонки. Подробные настройки см. ниже.

### Пользовательский выбор значения

Можно изменить источник и отображаемое значение для каждой колонки. Чтобы взять значение из другой колонки, используйте параметр `valueFrom`.

```yaml
other_name:
    label: Something Great
    valueFrom: name
```

Если нужно оставить исходное значение колонки, но отображать другое значение из атрибута модели, используйте параметр `displayFrom`.

```yaml
status_code:
    label: Status
    displayFrom: status_label
```

Чаще всего это применимо, когда используется [аксессор модели](../extend/database/mutators.md) для изменения отображаемого значения. Это полезно, когда нужно показывать одно значение, а сортировать и искать по другому.

```php
public function getStatusLabelAttribute()
{
    return title_case($this->status_code);
}
```

### Выбор вложенных значений

Иногда имеет смысл получить значение колонки из вложенной структуры данных, например из колонки [связи модели](../extend/database/relations.md) или [массива jsonable](../extend/system/models.md). Следующий пример извлекает значение, эквивалентное `$record->content->title` или `$record->content['title']`.

```yaml
content[title]:
    name: Title
    sortable: false
```

Единственный недостаток такого подхода — колонка не может участвовать в поиске или сортировке. Чтобы сделать колонку доступной для поиска и повысить производительность, рекомендуется дублировать значение в локальной таблице базы данных с помощью [событий модели](../extend/database/model.md). В качестве альтернативы можно использовать свойство `relation`, описанное ниже.

### Прямой выбор SQL

Свойство `select` позволяет создать колонку с пользовательским выражением select. Подходит любое корректное выражение SQL SELECT.

```yaml
full_name:
    label: Full Name
    select: concat(first_name, ' ', last_name)
```

### Выбор связанной колонки

Свойство `relation` позволяет отображать связанные колонки как часть запроса к базе данных, включая возможность поиска и сортировки по этой колонке. Параметр `relation` задаётся именем [связи модели](../database/relations.md). В следующем примере значение **name** берётся из атрибута связанной модели (например, `$model->name`).

```yaml
group_name:
    label: Group
    relation: groups
    select: name
```

Чтобы отобразить колонку с количеством связанных записей, используйте параметр `relationCount`.

```yaml
users_count:
    label: Users
    type: number
    relation: users
    relationCount: true
```

::: warning
Не называйте связи так же, как существующие колонки базы данных. Например, имя `group_id` может нарушить работу связи group из-за конфликта имён.
:::

### Подсказка (tooltip)

Свойство `tooltip` добавляет в заголовок колонки информационную иконку. При наведении отображается подсказка с дополнительным контекстом или пояснениями. Это помогает дать пользователям указания или уточнения по содержимому колонки.

```yaml
count:
    label: Count
    type: number
    tooltip: Number of users in the group
```

Помимо текста подсказки `title`, можно указать `icon` ([доступные иконки](../element/available-icons.md)) и `placement` (`right`, `bottom`, `left`, значение по умолчанию — `top`).

```yaml
count:
    label: Count
    type: number
    tooltip:
        title: Number of users in the group
        placement: bottom
        icon: icon-users
```
