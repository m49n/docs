# Компоненты

Компоненты (components) — ключевой инструмент для создания масштабируемых современных решений на October CMS. Каждый компонент реализует функциональность, расширяющую сайт. Компоненты могут выводить HTML-разметку на странице, но это не обязательно — другие важные возможности компонентов: [обработка AJAX-запросов](../../ajax/introduction.md), обработка отправок форм и управление жизненным циклом страницы, позволяющее внедрять переменные в страницы или реализовывать безопасность сайта.

Эта статья описывает основы компонентов и не рассматривает [использование компонентов с AJAX](../../ajax/handlers.md), [разработку компонентов](../../extend/cms-components.md) в составе плагинов или [компоненты, входящие в поставку](../components/section.md) October CMS.

## Введение

Компоненты доступны в редакторе панели администрирования. Их можно добавить на страницы, частичные представления (partials) и макеты (layouts), нажав кнопку Components на панели инструментов в любом открытом документе. Если используется текстовый редактор, компонент можно подключить к странице или макету, добавив его имя в секцию конфигурации шаблона. Ниже показано, как добавить демонстрационный компонент списка дел на страницу.

::: cmstemplate
```ini
title = "Components demonstration"
url = "/components"

[demoTodo]
maxItems = 20
```
```twig
<!-- HTML Content Here -->
```
:::

Так компонент инициализируется со свойствами, определёнными в секции компонента. У многих компонентов есть свойства, но это не обязательное требование. Некоторые свойства обязательны, другие имеют значения по умолчанию. Если непонятно, какие свойства поддерживает компонент, обратитесь к документации разработчика или используйте Inspector в редакторе бэкенда. Inspector открывается при клике на компонент в панели компонентов страницы или макета.

::: aside
Если компонент с одинаковым именем подключён и к странице, и к макету, приоритет будет у компонента страницы.
:::

При подключении компонента автоматически создаётся переменная страницы с именем компонента (в предыдущем примере — `demoTodo`). Компоненты, которые выводят HTML, можно отрендерить на странице тегом `{% component %}`, как показано ниже.

```twig
{% component 'demoTodo' %}
```

::: warning
Использование компонентов внутри частичных представлений ограничено — подробности см. в разделе [Динамические частичные представления](./partials.md).
:::

## Псевдонимы компонентов

Если два плагина регистрируют компоненты с одинаковым именем, можно подключить компонент, указав его полное имя класса и назначив ему *псевдоним*.

```ini
[October\Demo\Components\Todo demoTodoAlias]
maxItems = 20
```

Первый параметр секции — имя класса, второй — псевдоним компонента, который используется при подключении к странице. Если задан псевдоним, его нужно использовать везде в коде страницы при обращении к компоненту. В следующем примере используется псевдоним компонента:

```twig
{% component 'demoTodoAlias' %}
```

Псевдонимы позволяют разместить на одной странице несколько компонентов одного класса: сначала указывается короткое имя, затем псевдоним. Это позволяет выводить несколько экземпляров одного компонента.

```ini
[demoTodo todoA]
maxItems = 10
[demoTodo todoB]
maxItems = 20
```

## Использование внешних значений свойств

По умолчанию свойства инициализируются в секции конфигурации, где определён компонент, и значения статичны, как в примере ниже:

```ini
[demoTodo]
maxItems = 20
==
...
```

::: v-pre
Однако можно инициализировать свойства значениями из внешних параметров — параметров URL или параметров [частичного представления](partials.md) (для компонентов в частичных представлениях). Используйте синтаксис `{{ paramName }}` для значений, которые должны загружаться из переменных частичного представления:
:::

```ini
[demoTodo]
maxItems = {{ maxItems }}
==
...
```

Если в этом примере компонент **demoTodo** определён в частичном представлении, он будет инициализирован значением, полученным из переменной **maxItems** частичного представления:

```twig
{% partial 'my-todo-partial' maxItems='10' %}
```

Можно использовать точечную нотацию, чтобы получить вложенное значение из внешнего параметра:

```ini
[demoTodo]
maxItems = {{ data.maxItems }}
==
...
```

::: v-pre
Чтобы загрузить значение свойства из параметра URL, используйте синтаксис `{{ :paramName }}`, где имя начинается с двоеточия (`:`), например:
:::

```ini
[demoTodo]
maxItems = {{ :maxItems }}
==
...
```

Страница, к которой относится компонент, должна определить соответствующий [параметр URL](pages.md).

```ini
url = "/todo/:maxItems"
```

В бэкенде October можно использовать инструмент Inspector, чтобы назначать компоненту внешние значения. В Inspector не нужно вводить фигурные скобки — у каждого поля справа есть значок, открывающий редактор имени внешнего параметра. Укажите имя параметра как `paramName` для переменных частичного представления или `:paramName` для параметров URL.

## Передача переменных в компоненты

Компоненты могут быть рассчитаны на использование переменных во время рендеринга — аналогично [переменным частичных представлений](./partials.md), их можно указать после имени компонента в теге `{% component %}`. Переданные переменные явно переопределяют значение [свойств компонента](../../extend/cms-components.md), включая внешние значения.

В этом примере свойство **maxItems** компонента во время рендеринга будет равно *7*:

```twig
{% component 'demoTodoAlias' maxItems='7' %}
```

## Настройка разметки по умолчанию

::: aside
Разметка компонента по умолчанию — это шаблонный код, призванный показать базовый пример использования.
:::

Есть два способа изменить разметку компонента по умолчанию:

- скопировать разметку в тему;
- переопределить частичное представление компонента по одному.

Переопределение частичного представления компонента подходит лишь в ограничённых случаях. Обычно проще преобразовать частичное представление компонента в частичное представление CMS — различий минимум.

Рассмотрим пример компонента блога, который рендерится так.

::: cmstemplate
```ini
[blog]
```
```twig
{% component 'blog' %}
```
:::

Этот код фактически эквивалентен следующему.

::: cmstemplate
```ini
[blog]
```
```twig
{% partial 'blog::default' %}
```
:::

Если скопировать частичное представление **default.htm** компонента в тему и сохранить как **blog-default.htm**, его можно отрендерить тем же способом.

::: cmstemplate
```ini
[blog]
```
```twig
{% partial 'blog-default' %}
```
:::

Как видно, использовать частичные представления CMS для кастомизации содержимого просто, и это демонстрирует настоящую силу компонентов. Ситуации, когда тема должна переопределять частичные представления компонента, редки, и далее описаны подробнее.

### Перенос разметки по умолчанию в частичное представление

У каждого компонента есть точка входа — частичное представление **default.htm**, которое рендерится при вызове тега `{% component %}`. В следующем примере предполагается, что компонент называется **blogPost**.

::: cmstemplate
```ini
url = "blog/post"

[blogPost]
```
```twig
{% component "blogPost" %}
```
:::

Вывод берётся из файла плагина **components/blogpost/default.htm**. Можно скопировать всю разметку из этого файла и вставить её напрямую на страницу или в новое частичное представление, например **blog-post.htm**.

```twig
<h1>{{ __SELF__.post.title }}</h1>
<p>{{ __SELF__.post.description }}</p>
```

В разметке встречается переменная `__SELF__`, которая ссылается на объект компонента и должна быть заменена на псевдоним компонента, использованный на странице, в данном случае `blogPost`.

```twig
<h1>{{ blogPost.post.title }}</h1>
<p>{{ blogPost.post.description }}</p>
```

Это единственное изменение, необходимое, чтобы разметка компонента работала в любой части темы. Теперь её можно настраивать и рендерить с помощью частичного представления темы.

```twig
{% partial 'blog-post' %}
```

Этот процесс можно повторить для всех остальных частичных представлений в каталоге частичных представлений компонента.

### Переопределение частичных представлений компонента

Любые частичные представления компонента можно переопределить через частичные представления темы. Это полезно, когда компонент строго реализует определённые части разметки и предлагает возможность настроить отдельные области.

Например, компонент **channel** использует частичное представление **title.htm**.

::: cmstemplate
```ini
url = "mypage"

[channel]
```
```twig
{% component "channel" %}
```
:::

Частичное представление можно переопределить, создав в теме файл **partials/channel/title.htm**.

Сегменты пути файла расшифровываются так:

Segment | Description
------------- | -------------
**partials** | каталог частичных представлений темы
**channel** | псевдоним компонента (подкаталог частичных представлений)
**title.htm** | частичное представление компонента для переопределения

Имя подкаталога можно изменить, просто назначив компоненту псевдоним с тем же именем. Например, если присвоить компоненту **channel** псевдоним **foobar**, то изменится и каталог переопределения.

::: cmstemplate
```ini
[channel foobar]
```
```twig
{% component "foobar" %}
```
:::

Теперь частичное представление **title.htm** можно переопределить, создав в теме файл **partials/foobar/title.htm**.

## Компонент «View Bag»

::: aside
Компонент viewBag скрыт в панели бэкенда и доступен только при редактировании файлов. Его также могут использовать другие плагины для хранения данных.
:::

В October CMS есть специальный компонент `viewBag`, который можно использовать на любой странице или макете. Он позволяет определить произвольные свойства и обращаться к ним в разметке как к переменным. Хороший пример — определить активный пункт меню на странице.

::: cmstemplate
```ini
title = "About"
url = "/about.html"
layout = "default"

[viewBag]
activeMenu = "about"
```
```twig
<p>Page content...</p>
```
:::

Любое свойство компонента становится доступным на странице, в макете или частичном представлении через переменную `viewBag`. В следующем макете класс **active** добавляется к элементу списка, если `viewBag.activeMenu` равно **about**.

::: cmstemplate
```ini
description = "Default layout"
```
```twig
...

<!-- Main navigation -->
<ul>
    <li class="{{ viewBag.activeMenu == 'about' ? 'active' }}">About</li>
    ...
</ul>
```
:::

### AJAX-обработчики и частичные представления

Компоненты могут добавлять [AJAX-обработчики](../../ajax/introduction.md) и [частичные представления](./partials.md) в жизненный цикл темы, используя префикс имени компонента и двойное `::`. Например, все AJAX-обработчики, определённые компонентами, доступны глобально.

```html
data-request="onMyComponentHandler"
```

Если возникает конфликт имён, можно использовать полное имя.

```html
data-request="componentName::onMyComponentHandler"
```

Частичные представления, которые рендерятся вне компонента, должны использовать полное имя.

```twig
{% partial 'componentName::component-partial' %}
```

Подробнее о частичных представлениях компонентов см. в разделе [Разработка компонентов CMS](../../extend/cms-components.md).
