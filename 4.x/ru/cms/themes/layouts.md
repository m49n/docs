# Макеты

Макеты (layouts) задают общий каркас страниц, обычно содержащий элементы, которые повторяются на каждой странице, например шапку и подвал. Как правило, они содержат HTML-код с тегами HEAD, TITLE и BODY.

Файлы шаблонов макетов находятся в каталоге **layouts** темы. Они должны иметь расширение **htm**. Внутри файла макета следует использовать тег `{% page %}`, чтобы вывести содержимое страницы. Ниже приведён пример максимально простого макета.

```twig
<html>
    <body>
        {% page %}
    </body>
</html>
```

::: aside
Если используется макет из подкаталога, нужно указать имя подкаталога.
:::

Чтобы применить макет к [странице](./pages.md), необходимо указать имя файла макета (без расширения) в секции конфигурации страницы. Ниже пример шаблона страницы с макетом **default.htm**.

::: cmstemplate
```ini
url = "/"
layout = "default"
```
```twig
<p>Hello, world!</p>
```
:::

Когда запрашивается эта страница, её содержимое объединяется с макетом, точнее — тег `{% page %}` в макете заменяется содержимым страницы. Приведённые выше примеры генерируют следующую разметку:

```html
<html>
    <body>
        <p>Hello, world!</p>
    </body>
</html>
```

Макеты могут [подключать частичные представления (partials)](./partials.md). Это позволяет переиспользовать общие элементы разметки в разных макетах. Например, частичное представление может выводить ссылки на CSS и JavaScript сайта. Такой подход упрощает управление ресурсами — чтобы добавить новый скрипт, достаточно изменить одно частичное представление вместо редактирования всех макетов.

Секция конфигурации для макетов необязательна. Поддерживаются параметры **name** и **description**. Они необязательны и используются в интерфейсе бэкенда. Пример шаблона макета с описанием:

::: cmstemplate
```ini
description = "Basic layout example"
```
```twig
<html>
    <body>
        {% page %}
    </body>
</html>
```
:::

## Использование динамического заголовка страницы

Свойства `meta_title` и `meta_description` [страницы](pages.md) поддерживают подстановку переменных из жизненного цикла страницы. Следующий шаблон макета задаёт заголовок страницы на основе значения активной страницы.

```html
<html>
    <head>
        <title>{{ this.page.meta_title }} - October CMS</title>
    </head>
    <body>
        {% page %}
    </body>
<html>
```

Шаблон страницы может задать свой заголовок, используя синтаксис переменных Twig и значения из глобального окружения — в данном случае используется значение **post.title**.

```ini
url = "/blog"
meta_title = "{{ post.title }} - Blog"
```

> **Примечание:** поддерживаются только простые переменные Twig. Нельзя использовать фильтры, теги и функции.

## Плейсхолдеры

Плейсхолдеры (placeholders) позволяют страницам внедрять содержимое в макет. Плейсхолдеры определяются в шаблонах макетов тегом `{% placeholder %}`. В следующем примере показан макет с плейсхолдером **head** в секции HEAD.

```twig
<html>
    <head>
        {% placeholder head %}
    </head>
    ...
</html>
```

Страницы могут добавлять содержимое в плейсхолдеры тегами `{% put %}` и `{% endput %}`. Ниже показан простой шаблон страницы, который вставляет ссылку на CSS в плейсхолдер **head**, определённый в предыдущем примере.

::: cmstemplate
```ini
url = "/my-page"
layout = "default"
```
```twig
{% put head %}
    <link href="/themes/demo/assets/css/page.css" rel="stylesheet">
{% endput %}

<p>The page content goes here.</p>
```
:::

Дополнительные сведения о плейсхолдерах см. в [руководстве по разметке](../markup/tag-placeholder.md).

## Динамические макеты

Макеты, как и страницы, могут использовать любые возможности Twig. Подробности см. в разделе [Динамические страницы](pages.md) документации.

### Жизненный цикл макета

В секции PHP макета можно определить функции для обработки жизненного цикла страницы: `onInit`, `onStart`, `onBeforePageStart` и `onEnd`.

Функция `onInit` выполняется после инициализации всех компонентов и до обработки AJAX-запросов. `onStart` запускается в начале обработки страницы. `onBeforePageStart` выполняется после запуска [компонентов (components)](./components.md) макета, но до выполнения функции `onStart` страницы. `onEnd` выполняется после рендеринга страницы. Обработчики выполняются в следующем порядке:

1. Функция `onInit()` макета.
1. Функция `onInit()` страницы.
1. Функция `onStart()` макета.
1. Метод `onRun()` компонентов макета.
1. Функция `onBeforePageStart()` макета.
1. Функция `onStart()` страницы.
1. Метод `onRun()` компонентов страницы.
1. Функция `onEnd()` страницы.
1. Функция `onEnd()` макета.

### Доступ к методам и переменным

При обращении к переменным и методам внутри частичных представлений, страниц и макетов используется ближайший контекст. Рассмотрим следующую [секцию PHP-кода](./themes.md).

```php
function onStart()
{
    $this['myVariable'] = 'foo';
}

function myMethod()
{
    return 'bar';
}
```

В этом примере обращение к `myVariable` или `this.myMethod()` в Twig проверяет наличие в следующем порядке:

1. Частичное представление.
1. Страница.
1. Макет.

### Приоритетные макеты

В настройках макета можно указать атрибут `is_priority`, чтобы активировать приоритетный режим. В обычных условиях содержимое макета выводится после содержимого страницы. Это позволяет странице управлять свойствами макета, например заголовком или мета-описанием. Визуально порядок выглядит так:

```text
Layout (3) ← Page (1) → Partials (2)
```

В приоритетном режиме макет использует более естественный порядок загрузки, когда тег `{% page %}` выводится вместе с содержимым макета. Однако в этом режиме плейсхолдеры недоступны. Порядок загрузки приоритетного макета выглядит так:

```text
Layout (1) → Page (2) → Partials (3)
```

Это особенно полезно при [создании API-эндпоинтов](../resources/building-apis.md). В следующем примере логика страницы не выполнится, потому что тег страницы не вызывается.

::: cmstemplate
```ini
description = "API Layout"
is_priority = 1
```
```twig
{% if false %}
    {% page %}
{% endif %}
```
:::
