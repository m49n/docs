# Страницы

Любой сайт отдаёт как минимум одну страницу, и в October CMS страница представлена шаблоном страницы. Файлы шаблонов страниц находятся в каталоге **pages** темы. Имена файлов страниц не влияют на маршрутизацию, но стоит называть страницы в соответствии с их назначением. Файлы должны иметь расширение **htm**.

Секции конфигурации и Twig-разметки обязательны для страниц, а секция PHP — необязательна. Ниже показан самый простой пример главной страницы.

::: cmstemplate
```ini
url = "/"
```
```twig
<h1>Hello, world!</h1>
```
:::

## Конфигурация страницы

Конфигурация страницы определяется в секции конфигурации файла шаблона. Она задаёт параметры страницы, необходимые для маршрутизации и рендеринга страницы и её [компонентов (components)](./components.md), которые рассматриваются в отдельной статье. Страница поддерживает следующие параметры конфигурации:

Parameter | Description
------------- | -------------
**url** | URL страницы, обязательно. Синтаксис URL описан ниже.
**title** | заголовок страницы, обязательно.
**layout** | [макет (layout)](./layouts.md) страницы, необязательно. Если указан, содержит имя файла макета без расширения, например `default`.
**description** | описание страницы для бэкенда, необязательно.
**hidden** | скрытые страницы доступны только авторизованным пользователям бэкенда, необязательно.

### Синтаксис URL

URL страницы задаётся параметром конфигурации **url**. URL должен начинаться с символа прямого слеша и может содержать параметры. URL без параметров — фиксированные и строгие. В примере ниже URL страницы — `/blog`.

::: tip
URL страницы по умолчанию нечувствителен к регистру.

```ini
url = "/blog"
```
:::

URL с параметрами более гибкие. Страница со следующим шаблоном URL будет открываться по любому адресу вида `/blog/post/something`. Параметры URL доступны компонентам October или из секции PHP страницы.

```ini
url = "/blog/post/:post_id"
```

Так можно получить параметр URL в секции PHP страницы (подробнее см. раздел о динамических страницах).

::: cmstemplate
```ini
url = "/blog/post/:post_id"
```
```php
function onStart()
{
    $postId = $this->param('post_id');
}
```
```twig
```
:::

Имена параметров должны быть совместимы с именами переменных PHP. Чтобы сделать параметр необязательным, добавьте вопросительный знак после имени:

```ini
url = "/blog/post/:post_id?"
```

Параметры в середине URL не могут быть необязательными. В следующем примере параметр `:post_id` помечен как необязательный, но всё равно обрабатывается как обязательный.

```ini
url = "/blog/:post_id?/comments"
```

Необязательные параметры могут иметь значения по умолчанию, которые используются как запасной вариант, если фактическое значение отсутствует в URL. Значения по умолчанию не могут содержать звёздочки, вертикальные черты или вопросительные знаки. Значение по умолчанию указывается после **вопросительного знака**. В следующем примере параметр `category_id` примет значение `10` для URL `/blog/category`.

```ini
url = "/blog/category/:category_id?10"
```

Можно использовать регулярные выражения для валидации параметров. Чтобы добавить выражение, укажите вертикальную черту после имени параметра или вопросительного знака и впишите выражение. Символ прямого слеша в выражении недопустим. Примеры:

```ini
url = "/blog/:post_id|^[0-9]+$/comments" ; this will match /blog/10/comments

url = "/blog/:post_id|^[0-9]+$" ; this will match /blog/3

url = "/blog/:post_name?|^[a-z0-9\-]+$" ; this will match /blog/my-blog-post
```

Можно использовать специальный параметр *wildcard*, поставив **звёздочку** после имени. В отличие от обычных параметров, параметр wildcard может соответствовать одному или нескольким сегментам URL. В URL может быть только один такой параметр, его нельзя сочетать с регулярными выражениями и за ним не может следовать необязательный параметр.

```ini
url = "/blog/:category*/:slug"
```

Тем не менее, параметр wildcard можно сделать необязательным, добавив перед звёздочкой символ `?`.

```ini
url = "/blog/:slug?*"
```

Например, URL `/color/:color/make/:make*/edit` будет соответствовать `/color/brown/make/volkswagen/beetle/retro/edit` и вернёт такие значения параметров:

- color: `brown`
- make: `volkswagen/beetle/retro`

::: tip
Подкаталоги не влияют на URL страниц — URL определяется только параметром **url**.
:::

## Динамические страницы

В секции Twig шаблона страницы можно использовать любые [функции, фильтры и теги October CMS](../../markup/templating.md). Любой динамической странице нужны **переменные**, и их можно подготовить в секции PHP страницы или макета, либо [компонентами](./components.md). В этой статье показано, как готовить переменные в секции PHP.

### Жизненный цикл страницы

В секции PHP страниц и макетов можно определить специальные функции: `onInit`, `onStart` и `onEnd`. Функция `onInit` выполняется после инициализации всех компонентов и до обработки AJAX-запросов. `onStart` запускается в начале выполнения страницы. `onEnd` выполняется перед рендерингом страницы и после выполнения [компонентов](./components.md). В функциях `onStart` и `onEnd` можно передавать переменные в окружение Twig. Используйте `$this` с синтаксисом массива, чтобы передать переменные странице.

::: cmstemplate
```ini
url = "/"
```
```php
function onStart()
{
    $this['hello'] = "Hello world!";
}
```
```twig
<h3>{{ hello }}</h3>
```
:::

Следующий пример сложнее. В нём загружается коллекция записей блога из базы данных и выводится на странице (плагин `Acme\Blog` условный).

::: cmstemplate
```ini
url = "/blog"
```
```php
use Acme\Blog\Classes\Post;

function onStart()
{
    $this['posts'] = Post::orderBy('created_at', 'desc')->get();
}
```
```twig
<h2>Latest posts</h2>
<ul>
    {% for post in posts %}
        <h3>{{ post.title }}</h3>
        {{ post.content }}
    {% endfor %}
</ul>
```
:::

Стандартные переменные и расширения Twig, предоставленные October CMS, описаны в [руководстве по разметке](../../markup/templating.md). Последовательность вызова обработчиков описана в разделе [Динамические макеты](./layouts.md).

### Возврат собственного ответа

Любой метод жизненного цикла может остановить процесс и вернуть ответ — достаточно вернуть ответ из функции жизненного цикла. В примере ниже содержимое страницы не загружается, вместо этого браузер получит строку *Hello world!*:

```php
function onStart()
{
    return 'Hello world!';
}
```

Более практичный пример — инициировать перенаправление через фасад `Redirect`:

```php
public function onStart()
{
    return Redirect::to('http://google.com');
}
```

### Обработка форм

Обычные формы можно обрабатывать методами-обработчиками, определёнными в секции PHP страницы или макета (обработка AJAX-запросов описана в статье [AJAX Framework](../../ajax/introduction.md)). Используйте [Twig-функцию](../../markup/function/form.md) `form_open()`, чтобы объявить форму, которая вызывает обработчик.

```html
<form data-request="onHandleForm">
    <div>
        <label>Please enter a string</label>
        <input name="value"/>
    </div>

    <button data-attach-loading>
        Submit
    </button>
</form>

<p>Last submitted value: {{ lastValue }}</p>
```

Функцию `onHandleForm` можно определить в секции PHP страницы или макета.

```php
function onHandleForm()
{
    $this['lastValue'] = post('value');
}
```

Обработчик получает значение через функцию `post` и инициализирует переменную шаблона `lastValue`, которая отображается под формой в предыдущем примере.

::: tip
Если обработчик с тем же именем определён и в макете страницы, и в самой странице, и в [компоненте страницы](./components.md), October CMS выполнит обработчик страницы. Если обработчик определён и в компоненте, и в макете, будет выполнен обработчик макета. Приоритет обработчиков: страница, макет, компонент.
:::

Чтобы сослаться на обработчик конкретного компонента, укажите имя или псевдоним компонента в ссылке на обработчик:

```html
<form data-request="myComponent::onHandleForm">...</form>
```

## Страница 404

Если в теме есть страница с URL `/404`, она отображается, когда система не может найти запрошенную страницу.

## Страница ошибки

По умолчанию при ошибках показывается детальная страница с содержимым файла, номером строки и стеком вызовов, где возникла ошибка. Можно вывести собственную страницу ошибки, установив значение конфигурации `debug` в **false** в скрипте `config/app.php` и создав страницу с URL `/error`.

## Установка заголовка страницы

Заголовок страницы можно задать в PHP через объект страницы или в Twig с помощью [тега placeholder](../../markup/tag/placeholder.md).

### Использование свойств страницы

Свойства страницы доступны в секции PHP или в [компонентах](./components.md) через ссылку `$this->page`. В следующем примере атрибут `meta_title` получает новое значение.

```php
function onEnd()
{
    $this->page->meta_title = 'A different page title';
}
```

Переменная `{{ this.page }}` доступна в Twig через переменную `this.page`. Например, чтобы вернуть атрибут `meta_title` внутри макета.

```twig
<title>{{ this.page.meta_title }}</title>
```

::: tip
Подробнее о `this.page` см. в [руководстве по разметке](../../markup/property/this-page.md).
:::

### Использование плейсхолдеров

Тег `{% put %}` позволяет сохранить значение в плейсхолдере. В следующем примере задаётся переменная `pageTitle`.

```twig
{% put pageTitle = 'Yet another page title' %}
```

Twig-функция `placeholder()` используется для доступа к переменной внутри макета.

```twig
<title>{{ placeholder('pageTitle') }}</title>
```

Можно указать значение по умолчанию (второй аргумент) в качестве запасного варианта.

```twig
<title>{{ placeholder('pageTitle', this.page.meta_title) }}</title>
```

::: tip
Подробнее о теге placeholder см. в [статье о теге placeholder](../../markup/tag/placeholder.md).
:::

## Программное подключение ресурсов страницы

При необходимости можно подключать ресурсы (CSS и JavaScript) на страницах с помощью методов `addCss` и `addJs` контроллера. Это можно сделать в функции `onStart`, определённой в секции PHP страницы или [шаблона макета](./layouts.md).

```php
function onStart()
{
    $this->addCss('assets/css/hello.css');
    $this->addJs('assets/js/app.js');
}
```

Если путь, указанный в аргументе `addCss` или `addJs`, начинается со слеша (/), он считается относительно корня сайта. Если путь не начинается со слеша, он считается относительно темы.

Подключаемые ресурсы можно передавать массивом:

```php
function onStart()
{
    $this->addCss(['assets/css/hello.css', 'assets/css/goodbye.css']);
    $this->addJs(['assets/js/app.js', 'assets/js/nav.js']);
}
```

LESS и SCSS-файлы также можно подключать и компилировать через комбайнер.

```php
function onStart()
{
    $this->addCss(['assets/less/base.less']);
}
```

Второй аргумент `addCss` и `addJs` позволяет указать дополнительные атрибуты для подключаемых ресурсов:

```php
function onStart()
{
    $this->addJs(['assets/js/app.js', 'assets/js/nav.js'], ['defer' => true]);
}
```

Чтобы вывести подключённые ресурсы на страницах или [макетах](./layouts.md), используйте теги `{% styles %}` и `{% scripts %}`. Пример:

```twig
<head>
    ...
    {% styles %}
</head>
<body>
    ...
    {% scripts %}
</body>
```

::: tip
Дополнительные сведения о тегах `{% styles %}` и `{% scripts %}` см. в [руководстве по разметке](../../markup/tag/placeholder.md).
:::
