# Темы

::: aside
Активную тему задаёт параметр `active_theme` в файле `config/cms.php` либо настройка **Settings → Frontend Theme** в бэкенде. Настройка в бэкенде имеет приоритет над значением в `config/cms.php`.
:::

Темы полностью файловые и могут храниться в любой системе контроля версий, например Git. Эта страница даёт общее представление о темах October CMS. Подробности о страницах, частичных представлениях (partials), макетах (layouts) и контент-файлах смотрите в соответствующих статьях ниже.

Темы — это каталоги, которые по умолчанию находятся в директории **themes**. Темы могут содержать следующие объекты:

Object | Description
------------- | -------------
[Pages](./pages.md) | представляют страницы сайта.
[Partials](./partials.md) | содержат многократно используемые фрагменты HTML-разметки.
[Layouts](./layouts.md) | определяют каркас страницы.
[Content Files](./content.md) | текстовые блоки, HTML или блоки на [Markdown](http://daringfireball.net/projects/markdown/syntax), которые можно редактировать отдельно от страницы или макета.
**Asset Files** | ресурсные файлы, такие как изображения, CSS и JavaScript.

## Структура каталога

Ниже показан пример структуры каталогов темы. Каждая тема располагается в отдельном каталоге, и обычно активна только одна тема, которая отображает сайт. В примере показан каталог темы **website**.

::: dir
├── themes
|   └── website  _← Начало темы_
|       ├── `pages`
|       │   └── index.htm
|       ├── `layouts`
|       │   └── default.htm
|       ├── `partials`
|       │   └── sidebar.htm
|       ├── `content`
|       │   └── footer-contacts.md
|       └── `assets`
|           ├── css
|           |   └── my-styles.css
|           ├── js
|           └── images
:::

### Подкаталоги

October CMS поддерживает глубину до пяти подкаталогов для файлов **pages**, **partials**, **layouts** и **content**, а в каталоге **assets** вложенность не ограничена. Это упрощает организацию крупных сайтов. В примере ниже в каталогах **pages** и **partials** есть подкаталог **blog**, а в каталоге **content** — подкаталог **home**.

::: dir
├── themes
|   └── website
|       ├── pages
|       │   ├── index.htm
|       │   └── `blog`  _← Подкаталог страниц_
|       │       ├── index.htm
|       │       └── category.htm
|       ├── layouts
|       │   └── default.htm
|       ├── partials
|       │   ├── sidebar.htm
|       │   └── `blog`  _← Подкаталог частичных представлений_
|       │       └── category-list.htm
|       ├── content
|       │   ├── footer-contacts.md
|       │   └── `home`  _← Подкаталог контента_
|       │       └── intro.md
|       └── assets
:::

Чтобы обратиться к шаблону в подкаталоге, укажите имя подкаталога перед именем шаблона. Например, отрисовка частичного представления **category-list** из подкаталога **blog**.

::: tip
Пути шаблонов всегда абсолютные. Даже если в частичном представлении нужно подключить другое частичное представление из того же подкаталога, необходимо указать имя подкаталога.

```twig
{% partial "blog/category-list" %}
```
:::

## Структура шаблона

Шаблоны страниц, частичных представлений и макетов могут включать до трёх секций: **конфигурацию**, **PHP-код** и **Twig-разметку**. Секции разделяются последовательностью `==`.

::: cmstemplate
```ini
url = "/blog"
layout = "default"
```
```php
function onStart()
{
    $this['posts'] = [...];
}
```
```twig
<h3>Blog archive</h3>
{% for post in posts %}
    <h4>{{ post.title }}</h4>
    {{ post.content }}
{% endfor %}
```
:::

### Секция конфигурации

Секция конфигурации задаёт параметры шаблона. Поддерживаемые параметры отличаются для разных шаблонов CMS и описаны в соответствующих статьях документации. Секция конфигурации использует простой [INI-формат](http://en.wikipedia.org/wiki/INI_file), где строковые значения параметров берутся в кавычки. Пример секции конфигурации для шаблона страницы:

```ini
url = "/blog"
layout = "default"

[component]
parameter = "value"
```

### Секция PHP-кода

Код в секции PHP выполняется каждый раз перед рендерингом шаблона. Секция PHP необязательна для всех шаблонов CMS, а её содержимое зависит от типа шаблона, в котором она определена. Секция PHP может содержать необязательные открывающий и закрывающий теги PHP, чтобы включить подсветку синтаксиса в редакторах. Открывающий и закрывающий теги всегда должны находиться на отдельных строках относительно разделителя `==`.

::: cmstemplate
```ini
url = "/blog"
layout = "default"
```
```php
<?
function onStart()
{
    $this['posts'] = [...];
}
?>
```
```twig
<h3>Blog archive</h3>
{% for post in posts %}
    <h4>{{ post.title }}</h4>
    {{ post.content }}
{% endfor %}
```
:::

В секции PHP можно определять только функции и подключать пространства имён с помощью ключевого слова `use`. Другой PHP-код в секции PHP не допускается, потому что при разборе страницы эта секция преобразуется в PHP-класс. Ниже пример подключения пространства имён.

::: cmstemplate
```ini
url = "/blog"
layout = "default"
```
```php
<?
use Acme\Blog\Classes\Post;

function onStart()
{
    $this['posts'] = Post::get();
}
?>
```
```twig
```
:::

Как общее правило, переменные следует задавать через обращение к `$this` как к массиву, хотя для простоты можно использовать **доступ как к объекту только для чтения**, например:

```php
// Запись через массив
$this['foo'] = 'bar';

// Чтение через массив
echo $this['foo'];

// Чтение только для чтения через объект
echo $this->foo;
```

Определённые функции становятся доступными как методы через свойство `$this` в PHP и переменную `this` в Twig. В следующем примере определяется функция **doSomething**, а затем метод вызывается в обоих местах.

::: cmstemplate
```ini
url = "/"
```
```php
function onStart()
{
    $this['foo'] = $this->doSomething();
}

function doSomething()
{
    return 'bar';
}
```
```twig
<h3>{{ this.doSomething() }}</h3>
```
:::

### Секция Twig-разметки

Секция Twig определяет разметку, которую должен отрендерить шаблон. В секции Twig можно использовать функции, теги и фильтры, [предоставленные October CMS](../../markup/templating.md), все [встроенные возможности Twig](https://twig.symfony.com/doc/) или [добавленные плагинами](../../extend/twig-tags.md). Содержимое секции Twig зависит от типа шаблона (страница, макет или частичное представление). Дополнительные сведения об объектах Twig приведены далее в документации.

::: tip
Дополнительную информацию см. в [руководстве по разметке](../../markup/templating.md).
:::

## Журнал изменений темы

Поскольку макеты и страницы хранят большинство данных в простых файлах, содержимое можно случайно потерять. Например, смена макета страницы изменит её каркас и, как следствие, приведёт к потере данных.

October CMS может записывать каждое изменение темы в журнал — эта функция называется журналом изменений темы и по умолчанию отключена. Чтобы её включить, откройте **Settings → Log Settings** и активируйте **Log Theme Changes**.

Теперь журнал изменений темы доступен в **Settings → Theme Log**, где можно просмотреть сводку по каждому изменению. Эти сведения помогают принять решение, как откатить изменения при необходимости.
