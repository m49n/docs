# Поля контента

::: aside
Можно создать пользовательские поля контента, [расширяя Tailor](../../extend/tailor-fields.md).
:::

Поля контента — основа модуля Tailor, они определяют, как должно быть настроено и отображено поле. Эти определения часто находятся в свойстве **fields** чертежа.

```yaml
fields:
    name:
        label: Full Name
        type: text
```

::: tip
Полный список доступных полей приведён в разделе [«Элементы бэкенда»](../../element/form-fields.md).
:::

Для каждого поля можно указать общие свойства, если они применимы.

Property | Description
------------- | -------------
**label** | Имя, отображаемое пользователю рядом с полем.
**shortLabel** | Укороченная метка для списков и фильтров.
**type** | Определяет, как рендерить поле; см. [описание полей формы](../../element/form-fields.md). Значение по умолчанию: text.
**span** | Выравнивает поле формы по стороне. Варианты: auto, left, right, row, full, adaptive. Значение по умолчанию: `full`.
**spanClass** | Используется с вариантом span `row` для отображения формы в сетке Bootstrap, например `spanClass: col-4`.
**size** | Задаёт размер поля для полей, которые его поддерживают, например textarea.
**placeholder** | Отображает placeholder, если поле его поддерживает.
**comment** | Размещает поясняющий комментарий под полем.
**commentAbove** | Размещает комментарий над полем.
**commentHtml** | Разрешает HTML-разметку в комментарии. Значение по умолчанию: `false`.
**default** | Значение поля по умолчанию. Для виджетов `dropdown`, `checkboxlist`, `radio` и `balloon-selector` можно указать здесь ключ варианта, который будет выбран по умолчанию.
**tab** | Назначает поле вкладке.
**validation** | Определяет правила валидации поля формы, см. [статью о валидации](../../extend/services/validation.md) для описания правил.
**trigger** | Задаёт условия для поля с помощью [триггеров](../../element/form-fields.md).
**preset** | Позволяет задать значение поля на основе другого поля через [конвертер пресета ввода](../../element/form-fields.md).
**translatable** | Отключает перевод для поля при использовании `multisite` в определении чертежа.

## Свойства списка и фильтра

При отображении поля в списке или фильтре у каждого поля есть настройки по умолчанию. Можно переопределить их для конкретного поля — это подходит для небольших правок. Для более сложных сценариев рекомендуется определять столбцы и области (scopes) отдельно от полей (см. ниже).

Property | Description
------------- | -------------
**column** | Определяет отображение поля в списке, см. [описание столбцов списка](../../element/list-columns.md).
**scope** | Определяет отображение поля в фильтре, см. [описание областей фильтра](../../element/filter-scopes.md).

### Настройка поля

Например, можно указать разные метки через свойства `column` или `scope`.

```yaml
myfield:
    label: Form Label
    column:
        label: List Label
    scope:
        label: Filter Label
```

Если задать значения `false`, поле будет отключено и скрыто.

```yaml
myfield:
    label: Form Label
    column: false
    scope: false
```

Тип `column` можно установить в `invisible`, чтобы скрыть столбец в списке по умолчанию.

```yaml
myfield:
    label: Form Label
    column: invisible
```

### Внешняя конфигурация

Можно определять области и столбцы отдельно от полей формы, используя свойства `columns` и `scopes` в чертеже. При использовании внешней конфигурации стандартный вид будет заменён только указанными полями.

```yaml
scopes:
    myfield:
        label: Filter Label
        # [...]

columns:
    myfield:
        label: List Label
        # [...]

fields:
    myfield:
        label: Form Label
        # [...]
```

::: tip
Определение **fields** должно существовать, чтобы **columns** или **scopes** были допустимы. Чтобы скрыть поле из формы, установите `hidden: true`, а затем `hidden: false`, чтобы показывать его в столбце или области.
:::

Для столбцов списка можно использовать краткую запись. Если передать строку — заменится метка; `true` — столбец останется; `false` — столбец будет удалён; `invisible` — станет скрытым.

```yaml
columns:
    myfield: List Label   # новая метка
    myfield: true         # отображать
    myfield: false        # скрыть
    myfield: invisible    # по умолчанию скрыто
    myfield: [...]        # массив конфигурации
```

Области фильтра поддерживают аналогичные краткие записи.

```yaml
scopes:
    myfield: Filter Label # новая метка
    myfield: true         # отображать
    myfield: false        # скрыть
    myfield: [...]        # массив конфигурации
```

## Валидация полей формы

Можно указать правила валидации для полей формы через свойство `validation`, см. [статью о валидации](../../extend/services/validation.md) для описания правил.

```yaml
fields:
    myfield:
        label: Featured Text
        validation: "required|min:15"
```

Правила валидации также можно задать отдельно в файле чертежа через свойство `validation`. Это позволяет указывать пользовательские имена атрибутов и сообщения.

```yaml
validation:
    rules:
        myfield: "required|min:15"
    attributeNames:
        myfield: My Field
    customMessages:
        myfield.min: "My field has to be at least 15 characters long"

fields:
    myfield:
        label: Form Label
        # [...]
```

Правило `unique` настраивается автоматически и не требует указания имени таблицы.

```yaml
unique_field:
    label: Unique Field
    validation: unique
```

Правило `required` поддерживает модификаторы **create** и **update**, чтобы применять его только при создании или обновлении модели соответственно. В примере ниже поле обязательно, только если модель ещё не существует.

```yaml
password:
    label: Password
    validation: "required:create"
```

## Изменение базовых полей

У каждой записи чертежа есть несколько базовых полей, [определённых атрибутами модели](./models.md). Их можно модифицировать при соблюдении условий.

Запись включена по умолчанию, но это поведение можно изменить, указав новое значение по умолчанию для поля `is_enabled`.

```yaml
fields:
    is_enabled:
        default: false
```

Заполнитель (placeholder) поля `title` формируется исходя из имени чертежа, однако его можно заменить на более подходящий для конкретного случая, например «Имя и фамилия», «Название события» или «Название площадки».

```yaml
fields:
    title:
        placeholder: Event Title
```

Иногда поле `title` может быть необязательным, например при использовании [чертежа single](./blueprints.md). Можно установить `hidden` в `true`. Скрытие поля отключит встроенную валидацию.

```yaml
fields:
    title:
        hidden: true
```
