# Введение

<VideoBlockLink src="https://www.youtube.com/watch?v=_WMH4mlMdjk" title="Учебник по Tailor" description="В этом видео показано, как быстро создать полноценный блог с Tailor." prompt="Посмотреть учебник" />

Tailor — это функциональность, определяющая файловые структуры контента, которые использует сайт, например корпоративный блог или страницу команды. Tailor автоматически генерирует интерфейс бэкенда для управления записями и предоставляет компоненты (components) CMS для вывода и связи записей на фронтенде.

При работе с Tailor можно пропустить традиционный процесс разработки плагина и сразу перейти к описанию контента. Поля задаются в виде шаблонов-чертежей (blueprints), а данные сохраняются в специальных таблицах базы данных. Шаблон-чертёж может также определять навигацию и другие модификаторы.

## Структура каталогов

Чертежи — это файлы YAML, которые по умолчанию находятся в каталоге **app/blueprints**, а также в каталоге **themes/.../blueprints** выбранной [темы CMS](../themes/themes.md). Размещение чертежей зависит от контекста: **чертежи приложения** доступны глобально, а **чертежи темы** — только при активной теме.

### Чертежи приложения

Ниже приведён пример структуры каталога с чертежами. Каждый чертёж может находиться в любом каталоге и иметь произвольное имя файла. Чертежи можно организовывать в подкаталоги любой глубины вложенности.

::: dir
├── app
|   └── `blueprints`  _← Здесь начинаются чертежи (blueprints)_
|       ├── blog
|       │   └── blog.yaml
|       │   └── author.yaml
|       ├── about
|       │   └── about.yaml
|       ├── wiki
|       │   └── article.yaml
:::

### Чертежи темы

Ниже показан пример структуры чертежей внутри темы **demo**. Как и в каталоге приложения, чертежи могут располагаться в любом каталоге, иметь произвольные имена файлов и любую глубину вложенности. Пункты навигации админ-панели для этих чертежей появляются только при выбранной теме, что часто регулируется [настройками Multisite](../resources/multisite.md).

::: dir
├── themes
|   └── demo
|       ├── `blueprints`  _← Здесь начинаются чертежи (blueprints)_
|       │   └── settings.yaml
|       │   └── color-scheme.yaml
:::

## Типы чертежей

Свойство **type** чертежа определяет, как его следует реализовывать. Доступно несколько типов, и большинство чертежей задают [определения полей формы](../../element/form-fields.md).

Type | Description
------------- | -------------
Entry | стандартная структура контента с поддержкой черновиков.
Global | одиночная запись в базе данных, которую часто используют для настроек и конфигурации.
Mixin | определяет повторно используемые описания полей, которые можно импортировать и комбинировать с другими определениями полей.

Каждый тип чертежа описан подробнее в статье [«Чертежи»](./blueprints.md).

## Структура чертежа

::: aside
Чертежи полностью переносимы. Они используют внутренние идентификаторы и могут находиться в любом каталоге с произвольным именем файла.
:::

Чертежи определяются в синтаксисе YAML и всегда содержат три идентификатора: уникальный UUID, человеко-понятный handle и тип чертежа. Имя файла и папка чертежа используются лишь для организации и не служат идентификаторами. Все прочие свойства описаны в профильной статье документации для соответствующего чертежа.

```yaml
uuid: edcd102e-0525-4e4d-b07e-633ae6c18db6
handle: Blog\Post
type: entry
name: Post

fields:
    # [...]
```

Handle чертежа — удобочитаемый способ ссылки на объект чертежа. В примере выше можно обращаться к записям по handle.

::: tip
Handle следует соглашению об именовании, похожему на пространства имён PHP, и может включать разделитель обратная косая черта `\`.
:::

```ini
[section blog]
handle = "Blog\Post"
```

UUID чертежа — уникальный идентификатор, используемый при ссылках одного чертежа на другой, например когда поле подключает примесь (mixin). При первичном создании чертежа UUID можно опустить — он будет автоматически создан при первой миграции.

```yaml
_blog_content:
    source: edcd102e-0525-4e4d-b07e-633ae6c18db6
    type: mixin
```

## Интеграция с Multisite

По умолчанию чертежи не используют [возможности Multisite](../resources/multisite.md). Чтобы включить их, используйте свойство `multisite`. В этом режиме записи могут быть уникальными для каждого настроенного сайта.

```yaml
handle: Blog\Post
type: entry
# ...
multisite: true
```

Если Multisite включён, все поля чертежа становятся переводимыми. Чтобы сохранить единое значение поля, задайте свойство `translatable` в `false`. В примере ниже при сохранении записи поле **name** будет копироваться на каждый сайт.

```yaml
# ...
multisite: true

fields:
    name:
        label: Full Name
        type: text
        translatable: false
```

Можно указать значение **sync**, чтобы синхронизировать записи между сайтами — это полезно для категорий и тегов. В режиме sync каждая запись всегда присутствует на каждом сайте, хотя содержимое может отличаться.

```yaml
multisite: sync
```

При использовании [групп сайтов](../resources/multisite.md) записи распространяются на все сайты внутри группы. Чтобы синхронизировать записи между всеми сайтами, установите `multisite` в **all**.

```yaml
multisite: all
```

Значение **locale** синхронизирует записи между сайтами с одинаковой локалью.

```yaml
multisite: locale
```

## Миграция чертежей

Чертежи и их структура мигрируются в базе данных во время обычного процесса миграций. После ручного изменения файла чертежа следует выполнить команду `tailor:migrate`, чтобы обновить таблицы базы данных.

```bash
php artisan tailor:migrate
```

::: tip
Чертежи кешируются, когда режим отладки отключён. Команду миграции также можно использовать для очистки кеша чертежей.
:::

### Обновление контента

Чтобы удалить весь контент, управляемый Tailor, выполните команду `tailor:refresh`.

```bash
php artisan tailor:refresh
```

Для обновления конкретного чертежа используйте параметр `--blueprint` и укажите его handle.

```bash
php artisan tailor:refresh --blueprint="Blog\Post"
```

### Распространение контента

При использовании опции **sync** для Multisite можно ретроспективно распространить записи командой `tailor:propagate`.

```bash
php artisan tailor:propagate
```

Чтобы распространить один чертёж, используйте параметр `--blueprint` и укажите его handle.

```bash
php artisan tailor:propagate --blueprint="Blog\Category"
```

### Очистка контента

В общем случае Tailor никогда не удаляет столбцы таблиц и не стирает контент. Если поле удалено, столбец переименовывается вместо удаления. Например, старое поле `content` может появиться в таблице как `x_content_fb418fac`. Таблицы старых чертежей также сохраняются на случай восстановления.

Можно удалить неиспользуемые столбцы базы данных командой `tailor:prune`. Эта команда также удалит таблицы, у которых больше нет связанного чертежа.

```bash
php artisan tailor:prune
```

Чтобы удалять только поля, используйте модификатор `--fields`. Чтобы удалять только таблицы — модификатор `--tables`.

```bash
php artisan tailor:prune --fields
php artisan tailor:prune --tables
```

Для очистки данных одного чертежа воспользуйтесь параметром `--blueprint` и укажите его handle.

```bash
php artisan tailor:prune --blueprint="Blog\Post"
```
