# Ресурсы

Компонент (component) `resources` позволяет создавать новые переменные, добавлять заголовки и подключать ресурсы на странице. Компонент можно использовать на любой странице, в любом макете (layout) или частичном представлении (partial).

## Доступные свойства

Компонент поддерживает следующие свойства.

Property | Description
-------- | -------------
**js** | Массив файлов JavaScript в каталоге темы **assets/js**
**less** | Массив файлов LESS в каталоге темы **assets/less**
**scss** | Массив файлов SCSS в каталоге темы **assets/scss**
**css** | Массив файлов стилей в каталоге темы **assets/css**
**vars** | Добавляет переменные, доступные на странице или в макете.
**headers** | Добавляет заголовки к ответу страницы.

## Базовое использование

В следующем примере свойство `vars` создаёт новую переменную **activeNav**, которая становится доступной на протяжении жизненного цикла страницы, включая макеты и частичные представления, используемые на странице. Переменная читается через Twig-переменную `{{ activeNav }}`.

::: cmstemplate
```ini
[resources]
vars[activeNav] = 'blog'
```
```twig
{% if activeNav == 'blog' %}
    <p>The blog is active!</p>
{% endif %}
```
:::

## Внедрение переменных

Компонент ресурсов позволяет определить на странице любое количество переменных. Они становятся доступны в макете как обычные Twig-переменные.

```ini
[resources]
vars[activeNav] = 'blog'
```

Можно использовать и параметры из жизненного цикла страницы. В следующем примере переменная `activeNav` примет значение, найденное в параметре маршрута страницы `:slug`.

```ini
url = "mypage/:slug"

[resources]
vars[activeNav] = '{{ :slug }}'
```

Эта концепция применима и к переменным компонентов. В следующем примере поиск автора выполняется по `:slug`, найденному в маршруте страницы, после чего значение `author.id` присваивается переменной страницы **authorIdPage**.

```ini
url = "/author/:slug"

[section author]
handle = "Blog\\Author"
identifier = "slug"

[resources]
vars[authorIdPage] = 'Author ID is: {{ author.id }}'
```

## Внедрение ресурсов

Если макет включает стандартные теги `{% scripts %}` и `{% styles %}`, в эти плейсхолдеры можно внедрять ресурсы. Ресурсы будут объединены в единый скрипт или таблицу стилей.

Ресурсы, подключаемые через компонент `resources`, должны располагаться в определённых каталогах темы, перечисленных в свойствах. Например, частичное представление **blocks/carousel.htm** может выглядеть так:

::: cmstemplate
```ini
[resources]
css[] = "blocks/carousel.css"
scss[] = "blocks/carousel.scss"
less[] = "blocks/carousel.less"
js[] = "blocks/carousel.js"
```
```html
<!-- Carousel Contents Here -->
```
:::

Теперь при загрузке частичного представления на странице соответствующие скрипты и таблицы стилей будут внедрены в макет. Файлы ресурсов должны находиться по путям **assets/js/blocks/carousel.js** и **assets/less/blocks/carousel.less** соответственно.

```twig
<!-- Assets for the carousel are injected automatically -->
{% partial 'blocks/carousel' %}
```

::: tip
Если использовать частичное представление на странице дважды, ресурсы будут подключены только один раз.
:::

## Пользовательские заголовки

В качестве примера задания пользовательских заголовков можно отрисовать на странице XML-контент вместо HTML-контента. Это достигается внедрением заголовка `Content-Type` со значением **text/xml**. Заголовок будет отправлен вместе с ответом при загрузке страницы.

::: cmstemplate
```ini
url = "/blog/rss"

[resources]
headers[Content-Type] = 'text/xml'
```
```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">
    <!-- RSS contents here -->
</rss>
```
:::
