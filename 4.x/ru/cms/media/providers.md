# Провайдеры

Менеджер медиафайлов (Media Manager) по умолчанию использует провайдер Local Disk. Чтобы использовать функции Amazon S3, необходимо установить пакет Flysystem S3.

```bash
composer require league/flysystem-aws-s3-v3 "^3.0"
```

После изменения конфигурации менеджера медиафайлов следует сбросить его кеш. Это можно сделать, нажав кнопку **Refresh** на панели инструментов менеджера медиафайлов.

## Локальный диск

По умолчанию менеджер медиафайлов работает с подкаталогом **storage/app/media** в каталоге установки. Чтобы использовать Amazon S3, нужно обновить системную конфигурацию в файле **config/filesystems.php** и следовать инструкциям из этой статьи.

```php
'media' => [
    'driver' => 'local',
    'root' => storage_path('app/media'),
    'url' => '/storage/app/media',
    'visibility' => 'public',
    'throw' => false,
],
```

## Настройка доступа к Amazon S3

Чтобы использовать Amazon S3 с October CMS, необходимо создать бакет S3, папку в бакете и API-пользователя.

Зарегистрируйтесь в Amazon AWS или войдите в существующий аккаунт в AWS Console. Откройте панель управления S3. Создайте новый бакет и назначьте ему любое имя (имя бакета будет частью публичных URL файлов).

По умолчанию файлы в бакетах S3 недоступны напрямую. Чтобы сделать бакет публичным, вернитесь к списку бакетов и нажмите нужный бакет. Нажмите кнопку **Properties** в правой боковой панели. Раскройте вкладку **Permissions**. Нажмите ссылку **Edit bucket policy**. Вставьте следующий код в окно политики. Замените имя бакета на фактическое имя бакета:

```json
{
    "Version": "2008-10-17",
    "Id": "Policy1397632521960",
    "Statement": [
        {
            "Sid": "Stmt1397633323327",
            "Effect": "Allow",
            "Principal": {
                "AWS": "*"
            },
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::BUCKETNAME/*"
        }
    ]
}
```

Нажмите кнопку **Save**, чтобы применить политику. Эта политика предоставляет публичный доступ только на чтение ко всем папкам и каталогам в бакете. Если бакет используется и для других задач, можно открыть публичный доступ только к конкретной папке, указав имя каталога в параметре **Resource**:

```
"arn:aws:s3:::BUCKETNAME/media/*"
```

Также следует создать API-пользователя, которого October CMS будет использовать для управления файлами в бакете. В консоли AWS перейдите в раздел IAM. Откройте вкладку Users и создайте нового пользователя. Имя пользователя значения не имеет. Убедитесь, что флажок «Generate an access key for each user» установлен при создании пользователя. После создания пользователя AWS предоставит доступ к учётным данным безопасности — **Access Key ID** и **Secret Access Key**. Скопируйте ключи и временно сохраните их в текстовом файле.

Вернитесь к списку пользователей и нажмите созданного пользователя. В разделе **Permissions** нажмите кнопку **Attach Policy**. Выберите политику **AmazonS3FullAccess** в списке и нажмите кнопку **Attach Policy**.

Теперь есть вся информация для обновления конфигурации October CMS. Откройте скрипт **config/filesystems.php** и найдите секцию **disks**. Конфигурация медиа уже присутствует; необходимо изменить `driver` на **s3** и заменить параметры учётных данных API и информацию о бакете:

Параметр | Значение
------------- | -------------
**driver** | драйвер хранилища, который нужно использовать: local или s3.
**key** | значение **Access Key ID** ранее созданного пользователя.
**secret** | значение **Secret Access Key** ранее созданного пользователя.
**bucket** | имя бакета.
**region** | код региона бакета, см. ниже.
**url** | публичный путь к папке в бакете, см. ниже.

Код региона можно найти в консоли управления S3, в свойствах бакета. На вкладке Properties отображается имя региона, например Oregon. Для конфигурации драйвера S3 требуется код региона. Используйте эту таблицу, чтобы найти код для бакета. Дополнительно см. [документацию AWS](http://docs.aws.amazon.com/general/latest/gr/rande.html#s3_region).

Регион | Код
------------- | -------------
**US East (Ohio)** | us-east-2
**US East (N. Virginia)** | us-east-1
**US West (N. California)** | us-west-1
**US West (Oregon)** | us-west-2
**Asia Pacific (Hong Kong)** | ap-east-1
**Asia Pacific (Mumbai)** | ap-south-1
**Asia Pacific (Osaka-Local)** | ap-northeast-3
**Asia Pacific (Seoul)** | ap-northeast-2
**Asia Pacific (Singapore)** | ap-southeast-1
**Asia Pacific (Sydney)** | ap-southeast-2
**Asia Pacific (Tokyo)** | ap-northeast-1
**Canada (Central)** | ca-central-1
**China (Beijing)** | cn-north-1
**China (Ningxia)** | cn-northwest-1
**EU (Frankfurt)** | eu-central-1
**EU (Ireland)** | eu-west-1
**EU (London)** | eu-west-2
**EU (Paris)** | eu-west-3
**EU (Stockholm)** | eu-north-1
**South America (São Paulo)** | sa-east-1
**Middle East (Bahrain)** | me-south-1

Чтобы получить URL папки, откройте консоль AWS и перейдите в раздел S3. Перейдите в бакет и откройте созданную ранее папку. Загрузите любой файл в папку и нажмите на файл. Нажмите кнопку **Properties** в правой боковой панели. URL файла указан в параметре **Link**. Скопируйте URL, удалите из него имя файла и завершающий слеш.

Пример конфигурации после обновления:

```php
'disks' => [
    // ...
    'media' => [
        'driver' => 's3',
        'key'    => 'XXXXXXXXXXXXXXXXXXXX',
        'secret' => 'xxxXxXX+XxxxxXXxXxxxxxxXxxXXXXXXXxxxX9Xx',
        'region' => 'us-west-2',
        'bucket' => 'my-bucket',
        'url' => 'https://s3-us-west-2.amazonaws.com/your-bucket-name',
        'visibility' => 'public',
        'throw' => false
    ],
    // ...
]
```

Сохраните скрипт **config/filesystems.php**, и всё готово! Теперь можно использовать Amazon S3 с October CMS. Учтите, что можно дополнительно настроить CDN Amazon CloudFront для работы с бакетом. Эта тема не рассматривается в данном документе; см. [документацию CloudFront](http://aws.amazon.com/cloudfront/). После настройки CloudFront необходимо обновить параметр **url** в конфигурации файловых систем.

## Устранение неполадок

Самая распространённая проблема при использовании удалённых сервисов — ошибки SSL-соединения. Если возникают ошибки SSL, убедитесь, что на сервере установлены актуальные SSL-сертификаты доверенных удостоверяющих центров (CA).
