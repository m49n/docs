# Turbo Router

Турбо-маршрутизация — это реализация PJAX (push state и AJAX), которая обеспечивает производительность одностраничного приложения без дополнительной сложности клиентского фреймворка. При щелчке по ссылке страница автоматически заменяется на стороне клиента без стоимости полной загрузки страницы.

```twig
{% framework turbo %}
```

## Маршрутизация ссылок

Можно программно перейти по ссылке следующим образом.

```js
oc.visit(location);
```

Чтобы заменить текущий URL без добавления его в историю навигации, аналогично `window.history.replaceState`, укажите параметру `action` значение **replace**.

```js
oc.visit(location, { action: 'replace' });
```

Чтобы проверить, включён ли turbo router и следует ли его использовать.

```js
if (oc.useTurbo && oc.useTurbo()) {
    // Use PJAX
}
```

## Отключение маршрутизации

Чтобы отключить маршрутизацию PJAX на конкретной странице, можно принудительно выполнить полную перезагрузку, добавив в раздел head метатег `turbo-visit-control` со значением `reload`. Это отключит возможность только для входящих запросов.

```html
<head>
    <meta name="turbo-visit-control" content="reload" />
</head>
```

Чтобы полностью отключить PJAX на сайте, задайте значение `disable`. Это отключит возможность для всех входящих и исходящих запросов.

```html
<meta name="turbo-visit-control" content="disable" />
```

## Отключение для отдельных ссылок

По умолчанию все внутренние HTML-ссылки маршрутизируются через PJAX, но это можно отключить, пометив ссылки или их родительский контейнер атрибутом `data-turbo="false"`. Отключённые ссылки обрабатываются браузером как обычно.

```html
<a href="/" data-turbo="false">Disabled</a>
```

Можно повторно включить маршрутизацию, если предок отключил её:

```html
<div data-turbo="false">
    <a href="/" data-turbo="true">Enabled</a>
</div>
```

## Отключение прокрутки при переходе

При каждом переходе страница прокручивается к началу, как и большинство ссылок в браузере. Однако в некоторых случаях полезно сохранить позицию прокрутки, например когда ссылки работают как фильтры. Можно отключить прокрутку при переходе, используя атрибут `data-turbo-no-scroll` на элементе ссылки.

```html
<a href="/" data-turbo-no-scroll>Filter</a>
```

## Сохранение элементов страницы

Иногда на странице требуется оставить статические элементы, которые не должны обновляться при перерисовке страницы. Используйте атрибут `data-turbo-permanent` на родительском элементе. Элемент также должен иметь атрибут `id`, чтобы исходная страница сопоставлялась с новой, включая обработчики событий.

```html
<div id="main-navigation" data-turbo-permanent>...</div>
```

## Задание корневого пути

По умолчанию PJAX используется для всех ссылок в пределах одного доменного имени, а переход по любому другому URL приводит к полной загрузке страницы. В некоторых случаях приложение может располагаться в подкаталоге, и ссылки должны применяться только к корневому пути.

Например, если сайт расположен в `/app` и необходимо исключить ссылки на другой сайт в `/docs`, можно ограничить ссылки корневым путём. Установите корневой путь, добавив метатег `turbo-root` в раздел head страницы.

```html
<head>
    <meta name="turbo-root" content="/app">
</head>
```

## Страницы ошибок системы

При использовании PJAX, если сервер отвечает с кодом ошибки, таким как 404 или 500, заменяется весь элемент html, включая сценарии и таблицы стилей. Это предотвращает случайную замену элемента body содержимым, сгенерированным другим кодом приложения.

Отключить это поведение можно, добавив метатег `turbo-visit-control` в раздел head страницы со значением `error`. Это сообщит Turbo Router, что содержимое страницы ошибки создано родным приложением.

```html
<meta name="turbo-visit-control" content="error">
```

## Кэширование страниц

При включённом кэшировании turbo router ускоряет работу сайта, отображая повторно посещённые страницы без обращения к сети, что создаёт ощущение большей скорости. При щелчке по ссылке содержимое отображается из локального хранилища браузера, пока страница запрашивается в фоне. После завершения сетевого запроса показывается последняя версия страницы, поэтому страница рендерится дважды.

### Прослушивание события кэша

Можно прослушивать событие `page:before-cache`, если нужно подготовить документ перед помещением в кэш. Это полезно для сброса форм, свертывания элементов интерфейса или удаления сторонних контролов, чтобы страница была готова к повторному отображению.

```js
addEventListener('page:before-cache', function() {
    // Close any open submenus, etc.
});
```

### Определение загрузки страницы из кэша

Можно определить, что содержимое страницы берётся из кэша, по атрибуту `data-turbo-preview` на элементе HTML. На JavaScript это выглядит так:

```js
if (document.documentElement.hasAttribute('data-turbo-preview')) {
    // Page shown is loaded from cache
}
```

Или с помощью таблицы стилей:

```css
html[data-turbo-preview] {
    /* Hide overlays from previous view */
}
```

### Отключение кэша

Кэш страниц можно отключить для отдельных страниц с помощью метатега `turbo-cache-control` в разделе head. Значение **no-cache** полностью отключает кэш. Значение **no-preview** сохраняет кэшированную версию для навигации с помощью кнопок Back и Forward в браузере.

```html
<head>
    <meta name="turbo-cache-control" content="no-cache">
</head>
```

## Работа с JavaScript

При использовании PJAX содержимое страницы может загружаться динамически, что отличается от обычного поведения браузера. Чтобы учитывать это, используйте обработчик события `render`, который вызывается при каждой загрузке страницы, включая [AJAX-обновления](./update-partials.md).

```js
addEventListener('render', function() {
    // Page has rendered something new
});
```

Функция `oc.pageReady` используется для вызова кода, когда страница и сценарии готовы. Функция возвращает promise, который разрешается после загрузки всех сценариев страницы или сразу, если они уже загружены.

```js
oc.pageReady().then(() => {
    // Page has finished loading scripts
});
```

`oc.waitFor` — ещё одна полезная функция, которая ожидает появления объекта или переменной. Функция возвращает promise, который разрешается при обнаружении переменной.

```js
oc.waitFor(() => window.propName).then(() => [
    // window.propName is now available
]);
```

Второй аргумент задаёт интервал ожидания в миллисекундах; в примере ниже ожидание прекращается через две секунды.

```js
oc.waitFor(() => window.propName, 2000).then(() => {
    console.log('Found the variable!')
}).catch(() => {
    console.error('Gave up waiting...')
});
```

### Встроенные элементы script

Turbo router сохраняет сценарии внутри тега `<head>`, сравнивая различия. Если использовать теги script внутри тега `<body>`, сценарий будет выполняться при каждом рендеринге страницы, что может быть нежелательно.

Можно добавить `data-turbo-eval="false"`, чтобы сценарий выполнялся только при первой загрузке страницы. Сценарий не будет запускаться при запросах PJAX.

```html
<body>
    <script data-turbo-eval="false" src="{{ ['@framework.bundle']|theme }}"></script>
</body>
```
::: tip
Если сценарии размещаются внутри тега `<body>` из соображений производительности, рассмотрите возможность перенести их в тег `<head>` и использовать `<script defer>`.
:::

Чтобы выполнить встроенный код JavaScript только один раз, независимо от первой загрузки страницы или запроса PJAX, задайте уникальное значение атрибуту `data-turbo-eval-once`. Уникальное значение (например, `myAjaxPromise`) используется для определения, выполнялся ли сценарий ранее.

```html
<script data-turbo-eval-once="myAjaxPromise">
    // This script will run once only
    addEventListener('ajax:promise', function(event) {
        //
    });
</script>
```

### Создание идемпотентных контролов

::: aside
October CMS предоставляет дополнительную библиотеку, которая упрощает создание [идемпотентных контролов](./hot-controls.md).
:::

Когда происходит переход и инициализируются JavaScript-компоненты, важно, чтобы эти функции были идемпотентными. Проще говоря, идемпотентную функцию можно применять многократно без изменения результата сверх первоначального.

Один из способов сделать функцию идемпотентной — отслеживать факт выполнения, добавив значение в свойство `dataset` каждого обработанного элемента. Это полезно для внешних сценариев.

```js
addEventListener('page:loaded', function() {
    // Find my control
    var myControl = document.querySelector('.my-control');

    // Check if control has already been initialized
    if (!myControl.dataset.hasMyControl) {
        myControl.dataset.hasMyControl = true;

        // Initialize since this is the first time
        initializeMyControl(myControl);
    }
});
```

В целом более простой подход — позволить функции выполняться несколько раз и применять приёмы идемпотентности внутри неё. Например, перед созданием нового разделителя меню сначала проверять, существует ли он.

### Уничтожение контролов

Иногда необходимо привязать глобальные события только для определённой страницы, например назначить горячую клавишу для конкретного действия.

```js
addEventListener('keydown', myKeyDownFunction);
```

Чтобы предотвратить утечку события на другие страницы, следует удалить его с помощью события `page:unload`, которое уничтожит все события и контролы. Событие можно использовать один раз, чтобы безопасно удалить контролы и события.

```js
addEventListener('page:unload', function() {
    removeEventListener('keydown', myKeyDownFunction);
}, { once: true });
```

::: tip
October CMS включает дополнительную библиотеку для [создания контролов с уничтожением](./hot-controls.md).
:::

### Приостановка рендеринга

Если необходимо анимировать элементы, такие как выпадающие списки или выезжающие меню, перед загрузкой новой страницы, можно приостановить событие `page:before-render`, предотвратив стандартное поведение, и возобновить его с помощью функции `resume()` из деталей события.

```js
addEventListener('page:before-render', async (event) => {
    event.preventDefault();

    await animateOut();

    event.detail.resume();
});
```

::: warning
Имейте в виду, что событие **page:before-render** может сработать дважды: один раз из кэша и ещё раз после запроса нового содержимого страницы.
:::

## Глобальные события

AJAX-фреймворк инициирует несколько событий в течение жизненного цикла навигации и ответов страницы. События обычно инициируются на объекте `document`, а сведения доступны в свойстве `event.detail`.

Event | Описание
------------- | -------------
**render** | инициируется при обновлении страницы через PJAX или AJAX.
**page:click** | инициируется при щелчке по ссылке, маршрутизированной через turbo.
**page:before-visit** | инициируется перед переходом по адресу, кроме навигации через историю браузера.
**page:visit** | инициируется после запуска перехода по щелчку.
**page:request-start** | инициируется перед запросом страницы.
**page:request-end** | инициируется после завершения запроса страницы.
**page:before-cache** | инициируется перед помещением страницы в кэш.
**page:before-render** | инициируется перед рендерингом содержимого страницы.
**page:render** | инициируется после рендеринга страницы. Срабатывает дважды: из кэша и повторно после запроса нового содержимого.
**page:load** | инициируется один раз после первой загрузки страницы и снова при каждом посещении страницы.
**page:loaded** | аналогично `page:load`, но ожидает загрузки всех новых сценариев.
**page:updated** | похоже на `DOMContentLoaded`, но инициируется только при посещении страницы.
**page:unload** | вызывается, когда ранее загруженную страницу нужно уничтожить.

## Примеры использования

Следующий JavaScript выполняется при каждой загрузке страницы, включая сценарии.

```js
addEventListener('page:loaded', function() {
    // ...
});
```

## Работа с горячей перезагрузкой

В некоторых случаях turbo router может мешать при разработке сайта с горячей перезагрузкой или BrowserSync, например при использовании [Laravel Mix](https://laravel-mix.com/) в режиме разработки с `laravel-mix & browsersync`. Чтобы избежать этого, добавьте следующий код в конфигурацию `browserSync` webpack.

```js
snippetOptions: {
    rule: {
        match: /<\/head>/i,
        fn: function (snippet, match) {
            return '<meta name="turbo-visit-control" content="disable" />';
        }
   }
}
```
