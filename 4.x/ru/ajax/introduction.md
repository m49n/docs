# Введение

October CMS включает AJAX-фреймворк, который предоставляет полный набор возможностей и позволяет загружать данные с сервера без перезагрузки браузера. Эту же библиотеку можно использовать в темах CMS и где угодно в панели администратора.

AJAX-фреймворк доступен в двух вариантах: можно использовать [JavaScript API](./javascript-api.md) или [API атрибутов данных](./attributes-api.md). Для работы с API атрибутов данных не требуется знание JavaScript, чтобы применять AJAX в October CMS.

## Подключение фреймворка

::: aside
AJAX-фреймворк в теме CMS опционален, вместо него всегда можно подключить предпочитаемый фреймворк.
:::

При работе с [темой CMS](../../cms/themes/themes.md) достаточно подключить библиотеку с помощью тега Twig. Размести тег `{% framework %}` в любом месте страницы или макета. Это добавит ссылку на фронтенд-библиотеку JavaScript October CMS, например:

```twig
{% framework %}
```

### Дополнительные возможности

Тег `{% framework %}` поддерживает необязательный параметр **extras**, который подключает дополнительные файлы StyleSheet и JavaScript для таких возможностей, как [валидация форм](./features/validation.md), [индикаторы загрузки](./features/loaders.md) и [всплывающие сообщения](./features/flash-messages.md).

```twig
{% framework extras %}
```

Можно также указать параметр **turbo**, чтобы на каждой странице включить [турбо-маршрутизацию](./turbo-router.md).

```twig
{% framework extras turbo %}
```

## Как работают AJAX-запросы

Страница может отправить AJAX-запрос с помощью атрибутов данных или JavaScript. Каждый запрос вызывает **обработчик события** — также называемый [AJAX-обработчиком](./handlers.md) — на сервере и может обновлять элементы страницы через частичные представления. AJAX-запросы лучше всего работают с формами, поскольку данные формы автоматически отправляются на сервер. Рабочий процесс запроса выглядит так:

1. Браузер клиента отправляет AJAX-запрос, указывая имя обработчика и другие необязательные параметры.
2. Сервер находит [AJAX-обработчик](./handlers.md) и выполняет его.
3. Обработчик выполняет необходимую бизнес-логику и обновляет окружение, внедряя переменные страницы.
4. Сервер [рендерит частичные представления](./update-partials.md), запрошенные клиентом с помощью опции `update`.
5. Сервер отправляет ответ, содержащий разметку отрендеренных частичных представлений.
6. Клиентская часть фреймворка обновляет элементы страницы данными частичных представлений, полученными с сервера.

## Пример использования

Ниже приведён простой пример, который использует API атрибутов данных для определения формы с поддержкой AJAX. Форма отправит AJAX-запрос обработчику **onTest** и запросит обновление контейнера результата с помощью частичного представления **mypartial**.

::: tip
Данные формы `value1` и `value2` автоматически отправляются вместе с AJAX-запросом.

```html
<!-- AJAX enabled form -->
<form data-request="onTest" data-request-update="{ mypartial: '#myDiv' }">

    <!-- Input two values -->
    <input name="value1"> + <input name="value2">

    <!-- Action button -->
    <button type="submit">Calculate</button>

</form>

<!-- Result container -->
<div id="myDiv"></div>
```
:::

Частичное представление **mypartial** содержит разметку, которая считывает переменную `result`.

```twig
<p>The answer is {{ result }}</p>
```

Обработчик **onTest** получает данные формы с помощью [вспомогательного метода](../../extend/services/helpers.md) `input`, а затем передаёт результат в переменную страницы `result`.

```php
function onTest()
{
    $this['result'] = input('value1') + input('value2');
}
```

Пример можно прочитать так: «Когда форма отправляется, выполнить AJAX-запрос к обработчику **onTest**. После завершения обработчика отрендерить частичное представление **mypartial** и внедрить его содержимое в элемент **#myDiv**».
