# Публикация пакетов

October CMS использует [Composer](https://getcomposer.org/) для публикации пакетов и полностью с ним совместим, поэтому их документация применяется как расширение этой статьи.

Чтобы опубликовать плагин (plugin) или тему (theme) на маркетплейсе October CMS, сначала нужно стать автором и выбрать авторский код. Этот код определяет имена пакетов и не может быть изменён позже.

Пакет должен находиться в репозитории системы контроля версий, к которому может получить доступ шлюз October CMS, например [GitHub](https://github.com/) или [BitBucket](https://bitbucket.org/). Для приватных пакетов сервер может получить доступ с использованием учётных данных, которые предоставляются во время публикации.

Убедитесь, что `name` пакета заканчивается на **-plugin** или **-theme** соответственно. Это помогает другим находить пакет и соответствует [руководству для разработчиков](https://octobercms.com/help/guidelines/developer#package-naming).

::: warning
При обновлении плагинов или тем для совместимости с новыми версиями October CMS необходимо следовать [семантическому версионированию](https://semver.org/), чтобы защитить более старые сайты от ломающих изменений.
:::

## Публикация плагинов

При публикации плагина файл `composer.json` должен содержать как минимум следующий JSON. Обратите внимание, что имя пакета должно заканчиваться на **-plugin**, а также необходимо указать пакет `composer/installers` в зависимостях.

```json
{
    "name": "acme/blog-plugin",
    "type": "october-plugin",
    "description": "Enter a meaningful description here",
    "require": {
        "composer/installers": "~1.0"
    }
}
```

Плагин с кодом **Acme.Blog** будет иметь имя пакета composer `acme/blog-plugin` и установится в каталог **plugins/acme/blog**.

## Публикация тем

При публикации темы файл `composer.json` должен содержать как минимум следующий JSON. Обратите внимание, что имя пакета должно заканчиваться на **-theme**, а также необходимо указать пакет `composer/installers` в зависимостях.

```json
{
    "name": "acme/boilerplate-theme",
    "type": "october-theme",
    "description": "Enter a meaningful description here",
    "require": {
        "composer/installers": "~1.0"
    }
}
```

Тема с кодом **Acme.Boilerplate** будет иметь имя пакета composer `acme/boilerplate-theme` и установится в каталог **themes/boilerplate**.

## Объявление зависимостей

И плагины, и темы могут требовать конкретную версию October CMS, а также зависеть от других пакетов — просто добавьте их в файл composer.json.

### Требование версии October CMS

Достаточно потребовать пакет `october/rain` с нужным [шаблоном целевой версии](https://getcomposer.org/doc/articles/versions.md). Следующий пример требует, чтобы установка платформы использовала October CMS версии 3.1 или выше.

```json
"require": {
    "october/rain": ">=3.1"
}
```

### Требование другого плагина

Перейдите в каталог темы или плагина и откройте файл composer.json, чтобы добавить зависимость и целевую версию. Следующий пример подключает плагин Acme.Blog с [диапазоном версий 1.2](https://getcomposer.org/doc/articles/versions.md).

```json
"require": {
    "acme/blog-plugin": "^1.2"
}
```

Также убедитесь, что пакет добавлен в свойство `$require` в [регистрационном файле плагина](../system/plugins.md).

### Требование другой темы

Перейдите в каталог темы или плагина и откройте файл composer.json, чтобы добавить зависимость и целевую версию. Следующий пример подключает тему Acme.Vanilla с [диапазоном версий 1.2](https://getcomposer.org/doc/articles/versions.md).

```json
"require": {
    "acme/vanilla-theme": "^1.2"
}
```

Убедитесь, что этот пакет добавлен в свойство `require` в [информационном файле темы](../../cms/themes/settings.md).

### Разработка с пакетами сторонних разработчиков

Чтобы создать новый плагин или тему, использующие внешний пакет или библиотеку, установите её в корневой файл composer, а затем скопируйте определение в composer-файл плагина. Например, если плагин `acme/blog-plugin` должен зависеть от пакета `aws/aws-sdk-php`.

1. В корневом каталоге выполните `composer require aws/aws-sdk-php`. Пакет установится в корневой файл composer и будет проверен на совместимость с другими пакетами.
2. После завершения откройте корневой файл **composer.json**, чтобы найти новую зависимость. Например, там появится нечто подобное:

    ```json
    "require": {
        "aws/aws-sdk-php": "^3.158"
    }
    ```

3. Скопируйте это определение из корневого файла **composer.json** и добавьте его в файл **plugins/acme/blog/composer.json** плагина. Теперь зависимость доступна приложению и требуется плагином для использования другими.

## Тегирование релиза

Пакеты в October CMS следуют [семантическому версионированию](https://semver.org/), а Composer использует git для определения стабильности и влияния конкретного релиза.

### Семантическое версионирование

Семантическое версионирование — это процесс, защищающий старые сайты от ломающих изменений. Важно помнить, что по умолчанию Composer не будет автоматически обновлять мажорную версию.

Следующий путь обновления потребует **ручного процесса**:

- Обновление с `v1.0.0` до `v2.0.0`

Composer **автоматически обновляет** минорные и патч-версии:

- Обновление с `v1.2.0` до `v1.3.0`
- Обновление с `v1.3.5` до `v1.3.6`

Подробнее см. статью [Composer Versions and Constraints](https://getcomposer.org/doc/articles/versions.md).

### Просмотр тегов

Используйте команду `git tag`, чтобы вывести существующие теги пакета.

```bash
$ git tag
v1.0
v2.0
```

### Создание нового тега

Чтобы создать новый тег, добавьте (`-a`) версию с необязательным сообщением (`-m`).

```bash
git tag -a v2.0.1 -m "Version 2 is here!"
```

### Увеличение версии в файле

Помимо добавления тегов, следует также увеличить версию в [файле версий плагина](../system/plugins.md) или [настройках темы](../../cms/themes/settings.md). Этот файл сообщает шлюзу October CMS о последней версии и содержит историю предыдущих версий.

Чтобы понять, как это работает:

- Шлюз использует файл версий из **ветки по умолчанию** репозитория.
- Composer устанавливает и обновляет с использованием **последнего стабильного тега** репозитория.

Это означает, что файл версий в ветке по умолчанию всегда должен соответствовать последнему стабильному тегу в Git.

## Приватные плагины и темы

Composer позволяет добавлять приватные репозитории с GitHub и других провайдеров в проекты October CMS. Убедитесь, что выполнены те же инструкции по публикации плагинов и тем.

Во всех случаях необходимо хранить копию приватного плагина или темы в месте, доступном основному проекту. Команды `plugin:install` и `theme:install` можно использовать для установки приватных плагинов из удалённого или локального источника. Это добавит расположение в файл composer и установит пакет как любой другой.

### Установка из удалённого источника

При установке используйте опцию `--from`, чтобы указать расположение удалённого источника.

```bash
php artisan plugin:install Acme.Blog --from=git@github.com:acme/blog-plugin.git
```

Чтобы использовать определённую версию или ветку, добавьте опцию `--want`, например запросить версию ветки **develop**.

```bash
php artisan plugin:install Acme.Blog --from=git@github.com:acme/blog-plugin.git --want=dev-develop
```

::: tip
Если используется адрес репозитория с префиксом `git@`, Composer предпочитает версию исходного кода и клонирует репозиторий, чтобы можно было продолжать отправлять обновления обычным образом.
:::

### Установка из локального источника

Чтобы установить плагин через composer из того же исходного кода проекта.

```bash
php artisan plugin:install Acme.Blog --from=./plugins/acme/blog
```

Можно также использовать источник, расположенный на локальном или сетевом диске.

```bash
php artisan plugin:install Acme.Blog --from=/home/sam/private-plugins/acme-blog
```
