# Сортировка записей

October CMS предоставляет возможности для сортировки и реорганизации записей базы данных. Для поведений, поддерживающих структурированные списки, можно определить параметр **structure**, чтобы включить функцию. Для упорядочивания используются различные [трейты моделей](../database/traits.md), включая вложенные множества, простые деревья и сортируемые модели.

## Настройка поведения

Поведения бэкенда [List Controller](./list-controller.md) и [Relation Controller](../forms/form-controller.md) поддерживают возможность менять порядок записей с помощью свойства **structure** в соответствующей конфигурации. После определения страница отображает список записей с элементом перетаскивания, позволяющим сортировать и перестраивать их.

```yaml
# config_list.yaml

# ...

structure:
    showTree: true
    showReorder: true
    showSorting: false
    maxDepth: 2
```

Доступны следующие параметры конфигурации.

Property | Description
------------- | -------------
**showTree** | отображает иерархию дерева для записей родитель/потомок. Значение по умолчанию: `true`.
**treeExpanded** | определяет, должны ли узлы дерева быть раскрыты по умолчанию. Значение по умолчанию: `true`.
**showReorder** | отображает интерфейс для изменения порядка записей. Значение по умолчанию: `true`.
**showSorting** | включает сортировку записей и отключает структуру при сортировке. Значение по умолчанию: `true`.
**maxDepth** | задаёт максимально допустимое количество уровней при перестановке. Значение по умолчанию: `null`.
**dragRow** | позволяет перетаскивать всю строку, а не только элемент сортировки. Значение по умолчанию: `true`.
**permissions** | [права](../../extend/backend/permissions.md), которыми должен обладать текущий пользователь бэкенда для изменения структуры. Поддерживает строку для одного права или массив прав, из которых достаточно одного для предоставления доступа.

## Поддерживаемые типы моделей

В зависимости от требований можно использовать разные интерфейсы модели для управления вложенными и отсортированными записями. Поведение адаптируется в зависимости от применяемого трейта.

### Вложенное множество

Используйте трейт `NestedTree`, когда нужна фиксированная структура, включая отношения родитель—потомок и требование отображать записи в определённом порядке.

```php
class Category extends Model
{
    use \\October\\Rain\\Database\\Traits\\NestedTree;
}
```

Подробнее о трейте `NestedTree` см. в [документации по базе данных](../database/traits.md).

### Простое дерево

Используйте трейт `SimpleTree`, когда требуется базовое отношение родитель—потомок.

```php
class Category extends Model
{
    use \\October\\Rain\\Database\\Traits\\SimpleTree;
}
```

Подробнее о трейте `SimpleTree` см. в [документации по базе данных](../database/traits.md).

### Сортируемая модель

Используйте трейт `Sortable`, когда записи должны отображаться в определённом порядке.

```php
class User extends Model
{
    use \\October\\Rain\\Database\\Traits\\Sortable;
}
```

Подробнее о трейте `Sortable` см. в [документации по базе данных](../database/traits.md).

## Сортировка связанных записей

Сортировка связанных записей возможна с помощью [Relation Controller](../forms/relation-controller.md) и свойства **structure**. Поддерживаются следующие типы связей.

- [Has Many](../database/relations.md#relation-one-to-many) — использует трейт `Sortable` в связанной модели.
- [Belongs To Many](../database/relations.md#relation-many-to-many) — использует трейт `SortableRelation` в родительской модели (см. ниже).

### Трейт сортируемых связей модели

Используйте трейт `SortableRelation`, когда необходимо сортировать записи в промежуточной таблице, например в связи [Belongs To Many](../database/relations.md#many-to-many). Для трейта требуется определить свойство `pivotSortable` в описании связи, где значение — имя сортируемой колонки в промежуточной таблице.

```php
class User extends Model
{
    use \\October\\Rain\\Database\\Traits\\SortableRelation;

    /**
     * @var array belongsToMany
     */
    public $belongsToMany = [
        'roles' => [
            Role::class,
            'table' => 'users_roles',
            'pivotSortable' => 'sort_order',
        ]
    ];
}
```

В конфигурации связи следует включить свойство `showReorder` и отключить `showTree`.

```yaml
roles:
    #...
    structure:
        showReorder: true
        showTree: false
```
