# Создание компонентов CMS

Файлы и каталоги компонентов размещаются в подкаталоге **components** каталога плагина. Каждый компонент (component) включает PHP-файл с классом компонента и необязательный каталог частичных представлений компонента. Название каталога частичных представлений совпадает с именем класса компонента в нижнем регистре. Пример структуры каталога компонента:

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── `components`
|           |   ├── blogposts  _← Каталог частичных представлений_
|           |   |   └── default.htm  _← Разметка по умолчанию (необязательно)_
|           |   └── BlogPosts.php  _← Класс компонента_
|           └── Plugin.php
:::

Компоненты необходимо [зарегистрировать в регистрационном файле плагина](../extend/extending.md) методом `registerComponents`. Их можно настраивать через свойства и [типы инспектора](../element/inspector-types.md).

## Определение класса компонента

Команда `create:component` создаёт класс компонента и представление по умолчанию. Первый аргумент задаёт автора и название плагина. Второй аргумент задаёт имя класса компонента.

```bash
php artisan create:component Acme.Blog BlogPosts
```

Файл класса компонента определяет функциональность и свойства компонента. Имя файла должно совпадать с именем класса. Классы компонентов должны расширять `Cms\Classes\ComponentBase`. Компонент из следующего примера должен быть определён в файле **plugins/acme/blog/components/BlogPosts.php**.

```php
namespace Acme\Blog\Components;

class BlogPosts extends \Cms\Classes\ComponentBase
{
    public function componentDetails()
    {
        return [
            'name' => 'Blog Posts',
            'description' => 'Displays a collection of blog posts.',
            'icon' => 'icon-puzzle-piece'
        ];
    }

    /**
     * posts becomes available on the page as {{ component.posts }}
     */
    public function posts()
    {
        return ['First Post', 'Second Post', 'Third Post'];
    }
}
```

Метод `componentDetails` обязателен. Он должен возвращать массив с ключами `name` и `description`. Эти значения отображаются в пользовательском интерфейсе CMS в бэкенде.

Когда [компонент прикреплён к странице или макету](../cms/themes/components.md), свойства и методы класса становятся доступны на странице через переменную компонента, чьё имя совпадает с коротким именем компонента или его псевдонимом. Например, если компонент BlogPost из предыдущего примера определён на странице с коротким именем:

```ini
url = "/blog"

[blogPosts]
==
```

Получить доступ к методу `posts` можно через переменную `blogPosts`. Twig поддерживает обращение к методам через нотацию свойства, поэтому скобки не нужны.

```twig
{% for post in blogPosts.posts %}
    {{ post }}
{% endfor %}
```

### Регистрация компонента

Компоненты регистрируются переопределением метода `registerComponents` в [регистрационном файле плагина](../extend/extending.md). Это сообщает CMS о компоненте и задаёт его **короткое имя**. Пример регистрации компонента:

```php
public function registerComponents()
{
    return [
        \October\Demo\Components\Todo::class => 'demoTodo'
    ];
}
```

Так регистрируется класс компонента Todo с псевдонимом **demoTodo**. Дополнительную информацию об использовании компонентов см. в статье [о компонентах CMS](../cms/themes/components.md).

## Свойства компонента

При добавлении компонента на страницу или макет его можно настроить через свойства. Они определяются методом `defineProperties` класса компонента. Следующий пример показывает, как определить свойство с типом инспектора **string**.

```php
public function defineProperties()
{
    return [
        'maxItems' => [
            'title' => 'Max items',
            'description' => 'The most amount of todo items allowed',
            'default' => 10,
            'type' => 'string',
            'validation' => [
                'regex' => [
                    'message' => 'The Max Items property can contain only numeric symbols.',
                    'pattern' => '^[0-9]+$'
                ]
            ]
        ]
    ];
}
```

Метод должен возвращать массив, в котором ключи соответствуют свойствам, а значения — параметрам свойств. Эти ключи используются для доступа к значениям внутри класса компонента.

::: tip
Параметры свойств и доступные типы описаны в статье [о типах инспектора](../element/inspector-types.md).
:::

Внутри компонента значение свойства можно прочитать методом `property`:

```php
$this->property('maxItems');
```

Если значение не задано, можно передать значение по умолчанию вторым аргументом метода `property`:

```php
$this->property('maxItems', 6);
```

Все свойства можно получить массивом:

```php
$properties = $this->getProperties();
```

Чтобы обратиться к свойству из частичного представления Twig, используйте переменную `__SELF__`, которая ссылается на объект компонента:

```twig
{{ __SELF__.property('maxItems') }}
```

## Параметры маршрута

Компоненты могут напрямую получать значения параметров маршрута, заданные в [URL страницы](../cms/themes/pages.md).

```php
// Returns the URL segment value, eg: /page/:post_id
$postId = $this->param('post_id');
```

В некоторых случаях свойство компонента может быть жёстко заданным значением или ссылаться на значение из URL. В этом примере используется жёстко заданный идентификатор записи `2`:

```ini
url = "/blog/hard-coded-page"

[blogPost]
id = "2"
```

Либо значение можно динамически ссылать из URL страницы, используя [внешнее значение свойства компонента](../cms/themes/components.md).

```ini
url = "/blog/:my_custom_parameter"

[blogPost]
id = "{{ :my_custom_parameter }}"
```

В обоих случаях значение можно получить методом `property`:

```php
$this->property('id');
```

Чтобы получить имя параметра маршрута:

```php
// Returns "my_custom_parameter"
$this->paramName('id');
```

## Обработка цикла выполнения страницы

Компоненты могут участвовать в событиях цикла выполнения страницы, переопределяя метод `onRun` в классе компонента. Контроллер CMS выполняет этот метод при каждом открытии страницы или макета. Внутри метода можно передавать переменные в окружение Twig через свойство `page`:

```php
public function onRun()
{
    // This code will be executed when the page or layout is
    // loaded and the component is attached to it.

    $this->page['var'] = 'value'; // Inject some variable to the page
}
```

### Обработчики жизненного цикла страницы

При загрузке страницы October выполняет обработчики, определённые в PHP-секции макета, страницы и в классах компонентов. Последовательность выполнения обработчиков выглядит так:

1. Функция макета `onInit()`.
1. Функция страницы `onInit()`.
1. Функция макета `onStart()`.
1. Метод `onRun()` компонентов макета.
1. Функция макета `onBeforePageStart()`.
1. Функция страницы `onStart()`.
1. Метод `onRun()` компонентов страницы.
1. Функция страницы `onEnd()`.
1. Функция макета `onEnd()`.

### Инициализация компонента

Иногда нужно выполнить код при создании экземпляра класса компонента. Для инициализации логики переопределите метод `init` в классе — он выполняется до AJAX-обработчиков и до цикла выполнения страницы. Например, можно динамически подключить другой компонент к странице.

```php
public function init()
{
    $this->addComponent(\Acme\Blog\Components\BlogPosts::class, 'blogPosts');
}
```

### Прерывание с ответом

Как и все методы [жизненного цикла макета](../cms/themes/layouts.md), если метод `onRun` возвращает значение, цикл останавливается и возвращается ответ браузеру. В этом примере возвращается сообщение об отказе в доступе через фасад `Response`:

```php
public function onRun()
{
    if (true) {
        return Response::make('Access denied!', 403);
    }
}
```

Можно вернуть и ответ 404 из метода `onRun`:

```php
public function onRun()
{
    if (true) {
        $this->setStatusCode(404);
        return $this->controller->run('404');
    }
}
```

## AJAX-обработчики

Компоненты могут содержать AJAX-обработчики. Они определяются в классе компонента так же, как и в [коде страницы или макета](../ajax/handlers.md). Пример метода-обработчика AJAX в классе компонента:

```php
public function onAddItem()
{
    $value1 = post('value1');
    $value2 = post('value2');
    $this->page['result'] = $value1 + $value2;
}
```

Если псевдоним компонента — *demoTodo*, обработчик будет доступен как `demoTodo::onAddItem`. Подробности об AJAX — в статье [об обработчиках AJAX](../ajax/handlers.md).

## Разметка по умолчанию

Компоненты могут поставляться с разметкой по умолчанию для вставки на страницу через тег `{% component %}`, хотя это необязательно. Такая разметка хранится в **каталоге частичных представлений компонента**, имя которого совпадает с именем класса компонента в нижнем регистре.

Разметку по умолчанию нужно разместить в файле **default.htm**. Например, для компонента Demo ToDo она находится в файле **/plugins/october/demo/components/todo/default.htm**. Её можно вставить в любом месте страницы с помощью тега `{% component %}`:

::: cmstemplate
```ini
url = "/todo"

[demoTodo]
```
```twig
{% component 'demoTodo' %}
```
:::

Разметка по умолчанию может принимать параметры, переопределяющие свойства компонента во время рендеринга.

```twig
{% component 'demoTodo' maxItems="7" %}
```

Эти свойства недоступны в методе `onRun`, поскольку устанавливаются после завершения цикла страницы. Чтобы обработать их, переопределите метод `onRender` в классе компонента. Контроллер CMS выполняет этот метод до рендеринга разметки по умолчанию.

```php
public function onRender()
{
    // This code will be executed before the default component
    // markup is rendered on the page or layout.

    $this->page['var'] = 'Maximum items allowed: ' . $this->property('maxItems');
}
```

## Частичные представления компонента

Помимо разметки по умолчанию компоненты могут предоставлять дополнительные частичные представления для фронтенда или собственной разметки. Если компонент Demo ToDo содержит частичное представление **pagination**, оно будет лежать в **/plugins/october/demo/components/todo/pagination.htm** и может быть выведено так:

```twig
{% partial 'demoTodo::pagination' %}
```

Допускается более гибкий синтаксис, учитывающий контекст. Если вызов сделать из частичного представления компонента, он обратится к самому себе. Если вызов сделать из частичного представления темы, будет найден компонент на странице или макете с подходящим названием частичного представления и использован он.

```twig
{% partial '@pagination' %}
```

Несколько компонентов могут разделять частичные представления, если поместить файл в каталог **components/partials**. Частичные представления из этого каталога используются в качестве запасного варианта, когда стандартное частичное представление компонента не найдено. Например, общее частичное представление в **/plugins/acme/blog/components/partials/shared.htm** может быть выведено любым компонентом так:

```twig
{% partial '@shared' %}
```

### Ссылка на «себя»

Компоненты могут ссылаться на себя внутри своих частичных представлений через переменную `__SELF__`. По умолчанию она возвращает [короткое имя или псевдоним компонента](../cms/themes/components.md).

```twig
<form data-request="{{__SELF__}}::onEventHandler">
    [...]
</form>
```

Компоненты могут обращаться и к собственным свойствам.

```twig
{% for item in __SELF__.items() %}
    {{ item }}
{% endfor %}
```

Если из частичного представления компонента нужно отобразить другое частичное представление того же компонента, склейте переменную `__SELF__` с именем частичного представления:

```twig
{% partial __SELF__~"::screenshot-list" %}
```

### Уникальный идентификатор

Если один и тот же компонент используется на странице дважды, можно использовать свойство `id`, чтобы сослаться на конкретный экземпляр.

```twig
{{__SELF__.id}}
```

Значение `id` уникально при каждом выводе компонента.

```twig
<!-- ID: demoTodo527c532e9161b -->
{% component 'demoTodo' %}

<!-- ID: demoTodo527c532ec4c33 -->
{% component 'demoTodo' %}
```

## Рендеринг частичных представлений из кода

Частичные представления компонента можно отрендерить программно с помощью метода `renderPartial`. Он ищет частичное представление `component-partial.htm` внутри компонента и возвращает результат строкой. Второй параметр позволяет передать переменные представления. Для PHP действует та же логика поиска путей, что и для Twig: префикс `@` указывает на частичное представление внутри самого компонента.

```php
$content = $this->renderPartial('@component-partial.htm');

$content = $this->renderPartial('@component-partial.htm', [
    'name' => 'John Smith'
]);
```

Например, чтобы вернуть частичное представление в ответ на [AJAX-обработчик](../ajax/handlers.md):

```php
function onGetTemplate()
{
    return ['#someDiv' => $this->renderPartial('@component-partial.htm')];
}
```

Другой пример — переопределение всего ответа страницы, возвращая значение из цикла `onRun`. Этот код возвращает XML-ответ через фасад `Response`:

```php
public function onRun()
{
    $content = $this->renderPartial('@default.htm');
    return Response::make($content)->header('Content-Type', 'text/xml');
}
```

## Подключение ресурсов страницы через компоненты

Компоненты могут подключать ресурсы (CSS- и JavaScript-файлы) к страницам или макетам, к которым они прикреплены. Используйте методы контроллера `addCss` и `addJs`, например в методе `onRun` компонента.

```php
public function onRun()
{
    $this->addJs('/plugins/acme/blog/assets/javascript/blog-controls.js');
}
```

Если путь в аргументе `addCss` или `addJs` начинается со слэша (`/`), он считается относительным к корню сайта. Если слэш отсутствует, путь считается относительным к каталогу компонента.

Методы `addCss` и `addJs` принимают второй аргумент — массив атрибутов подключаемого ресурса.

```php
public function onRun()
{
    $this->addJs('/plugins/acme/blog/assets/javascript/blog-controls.js', ['defer' => true]);
}
```
