# Настройки на моделях

Настройки на моделях хранят значения в базе данных и могут переопределяться через пользовательский интерфейс в панели бэкенда.

## Настройки в базе данных

Плагины могут использовать конфигурацию, управляемую базой данных, применяя модели для хранения настроек и расширяя базовый класс `System\Models\SettingModel`. Эту модель можно напрямую использовать для создания формы настроек в бэкенде. Не нужно создавать таблицу базы данных и контроллер, чтобы собрать формы настроек на основе модели. Пример структуры каталогов для модели настроек:

::: dir
├── plugins
|   └── acme
|       └── demo
|           ├── models
|           |   ├── usersetting  _← Каталог конфигурации_
|           |   |   └── fields.yaml  _← Поля формы_
|           |   └── `UserSetting.php`  _← Класс модели_
|           └── Plugin.php
:::

Модели настроек можно зарегистрировать для отображения в [области настроек в панели бэкенда](./settings.md), но это необязательно — значения можно задавать и читать, как у любой другой модели.

### Определение класса модели

Классы моделей настроек должны расширять `System\Models\SettingModel` и, как любые модели, располагаться в подкаталоге **models** каталога плагина. Модель из следующего примера должна быть определена в файле **plugins/acme/demo/models/UserSetting.php**.

```php
namespace Acme\Demo\Models;

class UserSetting extends \System\Models\SettingModel
{
    public $settingsCode = 'acme_demo_settings';

    public $settingsFields = 'fields.yaml';
}
```

Свойство `$settingsCode` обязательно для моделей настроек. Оно задаёт уникальный ключ настроек, используемый при сохранении значений в базе данных.

Свойство `$settingsFields` обязательно, если планируется построить форму настроек в бэкенде на основе модели. Свойство указывает имя YAML-файла с описанием полей формы. Поля формы описаны в [статье о контроллере форм](../forms/form-controller.md). YAML-файл следует поместить в каталог с именем, соответствующим имени класса модели в нижнем регистре.

## Запись в модель настроек

Модель настроек содержит статический метод `set`, позволяющий сохранять одиночные или множественные значения. Можно также использовать стандартные возможности моделей, чтобы присвоить свойства и сохранить модель.

```php
use Acme\Demo\Models\UserSetting;

// Записать одно значение
UserSetting::set('api_key', 'ABCD');

// Записать массив значений
UserSetting::set(['api_key' => 'ABCD']);

// Записать значения объекта
$settings = UserSetting::instance();
$settings->api_key = 'ABCD';
$settings->save();
```

## Чтение из модели настроек

У модели настроек есть статический метод `get`, который позволяет загружать отдельные свойства. Кроме того, при создании экземпляра модели методом `instance` свойства загружаются из базы данных, и к ним можно обращаться напрямую.

```php
// Вывод: ABCD
echo UserSetting::instance()->api_key;

// Получить одиночное значение
echo UserSetting::get('api_key');

// Получить значение и вернуть значение по умолчанию, если его нет
echo UserSetting::get('is_activated', true);
```

## Интеграция с мультисайтом

Модели настроек могут предоставлять разные конфигурации для каждого сайта, определённого [конфигурацией мультисайта](../../cms/resources/multisite.md). Чтобы включить мультисайт, подключите в модели [трейт](../database/traits.md) `October\Rain\Database\Traits\Multisite` и определите свойство `$propagatable`, в котором можно указать поля, распространяемые на все сайты.

```php
namespace Acme\Demo\Models;

class UserSetting extends \System\Models\SettingModel
{
    use \October\Rain\Database\Traits\Multisite;

    public $settingsCode = 'acme_demo_settings';

    public $settingsFields = 'fields.yaml';

    protected $propagatable = [];
}
```
