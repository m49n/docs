# Введение

Существуют два основных способа конфигурирования системы плагинами. Сначала стоит определить, какой вариант лучше подходит под требования.

- [файловая конфигурация](./file-settings.md) без пользовательского интерфейса, хранится в файловой системе;
- [настройки на моделях](./model-settings.md) с необязательным пользовательским интерфейсом, хранятся в базе данных.

Использование настроек на моделях вместе со страницами бэкенда обеспечивает лучший пользовательский опыт, но требует больше усилий при первоначальной разработке. Файловая конфигурация подходит для параметров, которые редко меняются и не имеют интерфейса, например конфигурации политик.

## Регистрация страницы настроек

При использовании настроек на моделях их можно дополнительно зарегистрировать в специальной области для управления настройками и конфигурациями, доступной по ссылке **Settings** (Настройки) в главном меню.

Страницы настроек регистрируются переопределением метода `registerSettings` в [регистрационном файле плагина](../extending.md). Метод возвращает массив, где ключ соответствует элементу настроек, а значение описывает модель или контроллер настроек, который должен появиться в области настроек. Ниже показан пример регистрации модели настроек.

```php
public function registerSettings()
{
    return [
        'settings' => [
            'label' => 'User Settings',
            'description' => 'Manage user based settings.',
            'category' => 'CATEGORY_USERS',
            'icon' => 'icon-cog',
            'class' => \Acme\User\Models\UserSetting::class,
        ]
    ];
}
```

### Свойства настроек

При регистрации настроек для каждого ключа доступны следующие свойства.

Свойство | Описание
-------------- | -------------
**label** | задаёт ключ локализации для подписи меню, обязательно.
**category** | задаёт ключ локализации категории для группировки страниц настроек, обязательно.
**keywords** | задаёт ключевые слова для поиска настроек.
**order** | числовой вес, определяющий порядок отображения.
**icon** | имя иконки из [набора иконок October CMS](../../element/available-icons.md), необязательно.
**iconSvg** | SVG-иконка, используемая вместо стандартной; должна быть прямоугольной и может быть цветной, необязательно.
**url** | URL бэкенда, на который должен указывать пункт меню, например `Backend::url('author/plugin/controller/action')`.
**class** | класс модели, на который должен ссылаться пункт настроек, например `Acme\User\Models\UserSetting::class`.
**permissions** | массив разрешений, необходимых пользователю бэкенда для просмотра пункта меню (Примечание: прямой доступ по URL всё равно требует отдельной проверки разрешений), необязательно.
**context** | задаёт расположение элемента настроек: `system` или `mysettings`. Значение по умолчанию — `system`.
**size** | размер формы настроек при использовании свойства `class`. Допустимые значения: `tiny`, `small`, `medium`, `large`, `huge`, `giant`, `adaptive`. Значение по умолчанию — `large`.

Для совместимости с другими плагинами доступны следующие общие константы для свойства `category`.

<div class="content-list" markdown="1">

- CATEGORY_CMS
- CATEGORY_MISC
- CATEGORY_MAIL
- CATEGORY_LOGS
- CATEGORY_SHOP
- CATEGORY_TEAM
- CATEGORY_USERS
- CATEGORY_SOCIAL
- CATEGORY_SYSTEM
- CATEGORY_EVENTS
- CATEGORY_BACKEND
- CATEGORY_CUSTOMERS
- CATEGORY_MYSETTINGS
- CATEGORY_NOTIFICATIONS
- CATEGORY_GLOBALS
- CATEGORY_COLLECTIONS

</div>

Необязательный параметр `keywords` используется поиском по настройкам. Если ключевые слова не указаны, поиск будет использовать только подпись и описание элемента настроек.

## Связь с классом модели

При связывании с моделью через свойство `class` нет необходимости создавать собственный контроллер, что удобно в большинстве случаев. Следующий пример создаёт ссылку на модель настроек, подробнее описанную в [статье о настройках на моделях](./model-settings.md).

```php
public function registerSettings()
{
    return [
        'settings' => [
            'label' => 'User Settings',
            'description' => 'Manage user based settings.',
            'category' => 'Users',
            'icon' => 'icon-cog',
            'class' => \Acme\User\Models\UserSetting::class,
            'order' => 500,
            'keywords' => 'security location',
            'permissions' => ['acme.users.access_settings']
        ]
    ];
}
```

Для формы используется обобщённый бэкенд-контроллер с базовыми возможностями вроде сохранения и сброса значений к значениям по умолчанию. Активная навигация настраивается автоматически. Определённые разрешения также применяются контроллером.

## Связь с классом контроллера

Если в свойствах настроек указать страницу через `url`, можно создать собственный контроллер и связать его с областью настроек. В следующем примере показано, как добавить ссылку на страницу бэкенда.

```php
public function registerSettings()
{
    return [
        'location' => [
            'label' => 'Locations',
            'description' => 'Manage available user countries and states.',
            'category' => 'Users',
            'icon' => 'icon-globe',
            'url' => Backend::url('acme/user/locations'),
            'order' => 500,
            'keywords' => 'geography place placement'
        ]
    ];
}
```

### Определение класса страницы настроек

Контроллеры страниц настроек могут быть любыми [бэкенд-контроллерами](../system/controllers.md), однако для удобства можно унаследовать их от базового класса `Backend\Classes\SettingsController`. Этот класс автоматически регистрирует контекст навигации настроек в контроллере. Достаточно указать код настроек в свойстве `$settingsItemCode`, чтобы определить активный пункт меню.

```php
namespace Acme\Blog\Controllers;

class Posts extends \Backend\Classes\SettingsController
{
    public $settingsItemCode = 'location';

    public function index() {}
}
```
