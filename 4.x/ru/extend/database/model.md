# Запросы моделей

При запросе данных из базы модель получает значения в основном методами `get` или `first`, в зависимости от того, нужно ли получить несколько моделей или одну. Запросы, формируемые моделью, возвращают экземпляр `October\\Rain\\Database\\Builder`.

## Получение нескольких моделей

После создания модели и [соответствующей таблицы](./structure.md) можно извлекать данные из базы. Каждая модель работает как мощный [конструктор запросов](./query.md), позволяя выполнять запросы к таблице, связанной с моделью.

```php
$flights = Flight::all();
```

### Доступ к значениям столбцов

Имея экземпляр модели, можно получить значения столбцов, обратившись к соответствующему свойству. Например, пройдём по каждой записи `Flight`, возвращённой запросом, и выведем значение столбца `name`.

```php
foreach ($flights as $flight) {
    echo $flight->name;
}
```

### Добавление дополнительных ограничений

Метод `all` возвращает все результаты таблицы модели. Поскольку каждая модель служит [конструктором запросов](./query.md), можно добавлять ограничения и затем вызывать метод `get`, чтобы получить результаты:

```php
$flights = Flight::where('active', 1)
    ->orderBy('name', 'desc')
    ->take(10)
    ->get();
```

::: tip
Поскольку модели — это конструкторы запросов, полезно ознакомиться со всеми методами [конструктора запросов](./query.md). Любой из них можно использовать в запросах моделей.
:::

### Коллекции

Методы `all` и `get`, которые извлекают несколько результатов, возвращают экземпляр `Collection`. Этот класс предоставляет [множество полезных методов](./collection.md) для работы с результатами. Конечно, коллекцию можно перебирать как массив.

```php
foreach ($flights as $flight) {
    echo $flight->name;
}
```

### Обработка результатов частями

Если нужно обработать тысячи записей, используйте метод `chunk`. Он извлекает «порцию» моделей и передаёт их в указанный `Closure` для обработки. Метод `chunk` экономит память при работе с большими наборами данных.

```php
Flight::chunk(200, function ($flights) {
    foreach ($flights as $flight) {
        //
    }
});
```

Первый аргумент метода — количество записей в каждой «порции». `Closure`, переданный вторым аргументом, вызывается для каждой порции, полученной из базы.

## Получение одной модели

Помимо получения всех записей таблицы, можно извлекать отдельные записи методами `find` и `first`. Вместо коллекции они возвращают один экземпляр модели.

```php
// Получить модель по первичному ключу
$flight = Flight::find(1);

// Получить первую модель, удовлетворяющую условиям запроса
$flight = Flight::where('active', 1)->first();
```

### Исключения «не найдено»

Иногда нужно выбросить исключение, если модель не найдена. Это особенно полезно в маршрутах или контроллерах. Методы `findOrFail` и `firstOrFail` возвращают первый результат запроса. Если же результат не найден, будет выброшено исключение `Illuminate\\Database\\Eloquent\\ModelNotFoundException`.

```php
$model = Flight::findOrFail(1);

$model = Flight::where('legs', '>', 100)->firstOrFail();
```

При [разработке API](../system/routing.md), если исключение не перехвачено, пользователю автоматически вернётся ответ HTTP `404`, поэтому нет необходимости писать явные проверки для возврата `404` при использовании этих методов.

```php
Route::get('/api/flights/{id}', function ($id) {
    return Flight::findOrFail($id);
});
```

### Получение агрегатов

Также можно использовать `count`, `sum`, `max` и другие [агрегатные функции](./query.md), предоставляемые конструктором запросов. Эти методы возвращают соответствующее скалярное значение, а не экземпляр модели:

```php
$count = Flight::where('active', 1)->count();

$max = Flight::where('active', 1)->max('price');
```

## Вставка и обновление моделей

Вставка и обновление данных — ключевые возможности моделей, которые делают процесс значительно проще по сравнению с традиционными SQL-операторами.

### Простые вставки

Чтобы создать новую запись, создайте экземпляр модели, установите атрибуты и вызовите метод `save`:

```php
$flight = new Flight;
$flight->name = 'Sydney to Canberra';
$flight->save();
```

В этом примере мы создаём экземпляр модели `Flight` и задаём атрибут `name`. При вызове метода `save` запись будет вставлена в базу. Поля `created_at` и `updated_at` также заполнятся автоматически, поэтому задавать их вручную не нужно.

### Простые обновления

Метод `save` можно использовать и для обновления моделей, которые уже существуют в базе. Чтобы обновить модель, извлеките её, задайте нужные атрибуты и вызовите `save`. Поле `updated_at` обновится автоматически, поэтому вручную его задавать не требуется:

```php
$flight = Flight::find(1);
$flight->name = 'Darwin to Adelaide';
$flight->save();
```

Обновления можно выполнять и для набора моделей, удовлетворяющих условиям запроса. В этом примере все перелёты с `is_active = true` и `destination = 'Perth'` будут помечены как задержанные:

```php
Flight::where('is_active', true)
    ->where('destination', 'Perth')
    ->update(['delayed' => true]);
```

Метод `update` принимает массив пар «столбец — значение», которые нужно обновить.

### Массовое присвоение

Метод `create` позволяет сохранить новую модель в одну строку. Метод возвращает вставленный экземпляр. Однако перед этим нужно указать атрибут `fillable` или `guarded`, поскольку модели защищены от массового присвоения. Учтите, что `fillable` и `guarded` не влияют на отправку форм бэкенда, только на использование методов `create` или `fill`.

Уязвимость массового присвоения возникает, когда пользователь передаёт неожиданный параметр HTTP-запроса и этот параметр изменяет столбец базы, который менять не планировалось. Например, злоумышленник может отправить параметр `is_admin`, который затем попадёт в метод `create` модели, что позволит повысить свои права до администратора.

Для начала определите, какие атрибуты модели разрешено массово присваивать. Это делается с помощью свойства `$fillable` модели. Например, сделаем атрибут `name` модели `Flight` доступным для массового присвоения:

```php
class Flight extends Model
{
    /**
     * @var array fillable attributes that are mass assignable.
     */
    protected $fillable = ['name'];
}
```

После добавления атрибутов в список массового присвоения можно использовать метод `create`, чтобы вставить новую запись. Метод `create` возвращает сохранённый экземпляр модели:

```php
$flight = Flight::create(['name' => 'Flight 10']);
```

Свойство `$fillable` работает как «белый список» атрибутов для массового присвоения, а `$guarded` — как «чёрный список». Свойство `$guarded` должно содержать массив атрибутов, которые нельзя массово присваивать. Все остальные атрибуты будут доступны для массового присвоения. Используйте либо `$fillable`, либо `$guarded`, но не оба сразу:

```php
class Flight extends Model
{
    /**
     * The attributes that aren't mass assignable.
     *
     * @var array
     */
    protected $guarded = ['price'];
}
```

В примере выше все атрибуты, **кроме `price`**, доступны для массового присвоения.

### Другие способы создания

Иногда нужно лишь создать новый экземпляр модели. Это можно сделать методом `make`. Он просто вернёт новый экземпляр без сохранения или создания записи.

```php
$flight = Flight::make(['name' => 'Flight 10']);

// Функционально эквивалентно...
$flight = new Flight;
$flight->fill(['name' => 'Flight 10']);
```

Существуют ещё два метода массового создания моделей: `firstOrCreate` и `firstOrNew`. Метод `firstOrCreate` пытается найти запись по указанным парам столбец/значение. Если модель не найдена, будет вставлена запись с переданными атрибутами.

Метод `firstOrNew`, как и `firstOrCreate`, пытается найти запись в базе по указанным атрибутам. Однако если модель не найдена, будет возвращён новый экземпляр модели. Обратите внимание, что модель, возвращаемая `firstOrNew`, ещё не сохранена в базе. Чтобы сохранить её, вызовите `save` вручную:

```php
// Получить перелёт по атрибутам или создать его
$flight = Flight::firstOrCreate(['name' => 'Flight 10']);

// Получить перелёт по атрибутам или создать новый экземпляр
$flight = Flight::firstOrNew(['name' => 'Flight 10']);
```

## Удаление моделей

Чтобы удалить модель, вызовите метод `delete` на экземпляре модели:

```php
$flight = Flight::find(1);

$flight->delete();
```

В примере выше модель извлекается из базы перед вызовом `delete`. Однако если известен первичный ключ модели, можно удалить её без предварительного получения. Для этого вызовите метод `destroy`:

```php
Flight::destroy(1);

Flight::destroy([1, 2, 3]);

Flight::destroy(1, 2, 3);
```

Можно также выполнить запрос на удаление для набора моделей. В этом примере удаляются все перелёты, помеченные как неактивные:

```php
$deletedRows = Flight::where('active', 0)->delete();
```

::: warning
Важно: [события модели](../system/models.md) не запускаются при удалении записей напрямую через запрос.
:::

## Области запросов (scopes)

Области позволяют определить наборы ограничений, которые легко переиспользовать в приложении. Например, можно часто получать всех пользователей, которых считают «популярными». Чтобы определить область, добавьте к имени метода модели префикс `scope`.

```php
class User extends Model
{
    /**
     * scopePopular query to only include popular users.
     */
    public function scopePopular($query)
    {
        return $query->where('votes', '>', 100);
    }

    /**
     * scopeActive query to only include active users.
     */
    public function scopeActive($query)
    {
        return $query->where('is_active', 1);
    }
}
```

После определения области её методы можно вызывать при выполнении запросов. При вызове префикс `scope` указывать не нужно. Более того, можно объединять несколько областей, например:

```php
$users = User::popular()->active()->orderBy('created_at')->get();
```

Иногда требуется определить область, принимающую параметры. Для этого добавьте параметры в метод области. Они должны следовать после аргумента `$query`:

```php
class User extends Model
{
    /**
     * Scope a query to only include users of a given type.
     */
    public function scopeApplyType($query, $type)
    {
        return $query->where('type', $type);
    }
}
```

Теперь при вызове области можно передавать параметры:

```php
$users = User::applyType('admin')->get();
```
