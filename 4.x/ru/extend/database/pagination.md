# Постраничная навигация

## Базовое использование

Существует несколько способов разбивать записи на страницы, самый распространённый — вызвать метод `paginate` у запроса или модели. Он вернёт специальную коллекцию с дополнительными методами для вывода результатов.

### Постраничная навигация для конструктора запросов

Существует несколько способов пагинации. Самый простой — использовать метод `paginate` у [конструктора запросов](./query.md) или [запроса модели](./model.md). Метод `paginate` автоматически устанавливает нужные `limit` и `offset` на основе текущей страницы, которую просматривает пользователь. По умолчанию текущая страница определяется значением параметра `?page` в строке запроса HTTP. Это значение определяется автоматически и автоматически вставляется в ссылки, которые генерирует пагинатор.

Сначала рассмотрим вызов метода `paginate` у запроса. В этом примере единственный аргумент — количество элементов, которые нужно выводить «на страницу». Укажем, что нужно выводить по `15` элементов на странице.

```php
$users = Db::table('users')->paginate(15);
```

::: warning
В настоящее время пагинация с оператором `groupBy` выполняется неэффективно. Если необходимо использовать `groupBy` с результатом, разбитым на страницы, рекомендуется вручную выполнить запрос к базе и создать пагинатор.
:::

#### Простая пагинация

Если нужно отобразить только ссылки «Следующая» и «Предыдущая», можно использовать метод `simplePaginate`, который выполняет более эффективный запрос. Это особенно полезно для больших наборов данных, если не требуется выводить ссылку на каждую страницу.

```php
$users = Db::table('users')->simplePaginate(15);
```

#### Указание номера страницы

По умолчанию пагинатор берёт номер текущей страницы из параметра `?page`. Можно указать номер страницы методами `paginateAtPage` и `simplePaginateAtPage`. Им передаётся количество записей на странице (первый аргумент) и номер текущей страницы (второй аргумент).

```php
$recordsPerPage = 15;
$currentPage = 1;

$users = Db::table('users')->paginateAtPage($recordsPerPage, $currentPage);

$users = Db::table('users')->simplePaginateAtPage($recordsPerPage, $currentPage);
```

#### Пользовательское имя параметра

Методы `paginateCustom` и `simplePaginateCustom` позволяют указать собственное имя параметра строки запроса. В следующем примере для определения номера страницы используется параметр `?secondPage`.

```php
$recordsPerPage = 15;

$users = Db::table('users')->paginateCustom($recordsPerPage, 'secondPage');

$users = Db::table('users')->simplePaginateCustom($recordsPerPage, 'secondPage');
```

### Постраничная навигация для моделей

Пагинировать можно и [запросы моделей](./model.md). В этом примере разбиваем записи модели `User` по `15` элементов на страницу. Как видно, синтаксис почти совпадает с пагинацией конструктора запросов:

```php
$users = User::paginate(15);
```

Разумеется, перед вызовом `paginate` можно добавлять другие ограничения запроса, например условия `where`:

```php
$users = User::where('votes', '>', 100)->paginate(15);
```

Также можно использовать метод `simplePaginate` при пагинации моделей:

```php
$users = User::where('votes', '>', 100)->simplePaginate(15);
```

Можно указать номер страницы вторым аргументом: здесь мы выводим по `15` элементов на страницу и указываем, что находимся на странице `2`:

```php
$users = User::where('votes', '>', 100)->paginate(15, 2);
```

### Ручное создание пагинатора

Иногда нужно создать экземпляр пагинатора вручную, передав ему массив элементов. Можно создать `Illuminate\Pagination\Paginator` или `Illuminate\Pagination\LengthAwarePaginator` в зависимости от задачи.

Класс `Paginator` не требует знать общее количество элементов в наборе, поэтому у него нет методов для получения номера последней страницы. `LengthAwarePaginator` принимает почти те же аргументы, что и `Paginator`, но дополнительно требует общее количество элементов набора.

Другими словами, `Paginator` соответствует методу `simplePaginate` конструктора запросов и моделей, а `LengthAwarePaginator` — методу `paginate`.

Создавая экземпляр пагинатора вручную, нужно самостоятельно «нарезать» массив результатов, передаваемый пагинатору. Если не уверены, как это сделать, ознакомьтесь с функцией PHP [array_slice](http://php.net/manual/en/function.array-slice.php).

## Отображение результатов в представлении

При вызове методов `paginate` или `simplePaginate` у конструктора запросов или модели вы получите экземпляр пагинатора. Метод `paginate` возвращает `Illuminate\Pagination\LengthAwarePaginator`, а `simplePaginate` — `Illuminate\Pagination\Paginator`. Эти объекты предоставляют несколько методов для описания набора результатов. Кроме того, объекты пагинатора являются итераторами и их можно перебирать как массив.

Получив результаты, можно вывести их и отобразить ссылки страниц с помощью PHP или [функции Twig Pager](../../markup/function/pager.md).

```php
<div class="container">
    <?php foreach ($users as $user): ?>
        <?= $user->name ?>
    <?php endforeach ?>
</div>

<?= $users->links() ?>
```

Метод `render` выводит ссылки на остальные страницы набора результатов. Каждая ссылка уже содержит корректный параметр `?page`. HTML, который генерирует метод `render`, совместим с [CSS-фреймворком Bootstrap](https://getbootstrap.com).

::: tip
При вызове метода `render` в шаблоне Twig используйте фильтр `|raw`, чтобы HTML-ссылки не экранировались.
:::

#### Настройка URI пагинатора

Метод `setPath` позволяет указать собственный URI, который будет использовать пагинатор при генерации ссылок. Например, чтобы пагинатор создавал ссылки вида `http://example.tld/custom/url?page=N`, передайте `custom/url` методу `setPath`:

```php
$users = User::paginate(15);
$users->setPath('custom/url');
echo $users->render();
```

#### Добавление параметров к ссылкам пагинатора

Чтобы добавить параметры к строке запроса ссылок пагинатора, используйте метод `appends`. Например, чтобы добавить `&sort=votes` к каждой ссылке, вызовите `appends` так:

```php
echo $users->appends(['sort' => 'votes'])->render();
```

Если нужно добавить «якорь» к URL пагинатора, используйте метод `fragment`. Например, чтобы добавить `#foo` в конец каждой ссылки, вызовите `fragment`:

```php
echo $users->fragment('foo')->render();
```

#### Дополнительные вспомогательные методы

Получить дополнительную информацию о пагинации можно через следующие методы экземпляров пагинатора:

```php
$results->count()
$results->currentPage()
$results->hasMorePages()
$results->lastPage() // недоступно при использовании simplePaginate
$results->nextPageUrl()
$results->perPage()
$results->previousPageUrl()
$results->total() // недоступно при использовании simplePaginate
$results->url($page)
```

## Преобразование результатов в JSON

Классы результатов пагинации реализуют контракт `Illuminate\Contracts\Support\JsonableInterface` и предоставляют метод `toJson`, поэтому преобразовать результаты в JSON очень просто. Можно также преобразовать экземпляр пагинатора в JSON, просто вернув его из маршрута или обработчика AJAX:

```php
Route::get('users', function () {
    return User::paginate();
});
```

JSON, возвращаемый пагинатором, содержит метаданные, такие как `total`, `current_page`, `last_page` и другие. Сами объекты результатов доступны по ключу `data` в JSON-массиве. Пример JSON, который вернёт маршрут с пагинатором:

#### Пример JSON пагинатора

```json
{
    "total": 50,
    "per_page": 15,
    "current_page": 1,
    "last_page": 4,
    "next_page_url": "http://octobercms.app?page=2",
    "prev_page_url": null,
    "from": 1,
    "to": 15,
    "data":[
        {
            // Result Object
        },
        {
            // Result Object
        }
    ]
}
```
