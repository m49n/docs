# События

## Базовое использование

Класс `Event` предоставляет простую реализацию шаблона наблюдатель (observer), позволяя подписываться и отслеживать события в приложении. Например, можно обработать вход пользователя в систему и обновить дату его последнего входа.

```php
Event::listen('auth.login', function($user) {
    $user->last_login = new DateTime;
    $user->save();
});
```

Это событие становится доступным через метод `Event::fire`, который вызывается как часть логики входа пользователя, делая её расширяемой.

```php
Event::fire('auth.login', [$user]);
```

::: tip
Полный список событий, доступных в самом October CMS, см. в [API-документации](https://octobercms.com/docs/api).
:::

## Подписка на события

Метод `Event::listen` в первую очередь используется для подписки на события и может вызываться в любом месте кода приложения. Первый аргумент — имя события.

```php
Event::listen('acme.blog.myevent', ...);
```

Вторым аргументом может быть замыкание, определяющее, что должно произойти при срабатывании события. Замыкание может принимать дополнительные аргументы, переданные событием при вызове.

```php
Event::listen('acme.blog.myevent', function($arg1, $arg2) {
    // Do something
});
```

Также можно передать ссылку на любой вызываемый объект или отдельный класс события — он будет использоваться вместо замыкания.

```php
Event::listen('auth.login', [$this, 'LoginHandler']);
```

::: tip
Вызываемый метод может определить все, некоторые или ни одного из аргументов. В любом случае событие не вызовет ошибок, если только не указано слишком много аргументов.
:::

### Где регистрировать слушателей

Наиболее распространённое место — метод `boot` [регистрационного файла плагина](../extending.md).

```php
class Plugin extends PluginBase
{
    // ...

    public function boot()
    {
        Event::listen(...);
    }
}
```

Кроме того, плагины могут содержать файл **init.php** в каталоге плагина, где можно разместить логику регистрации событий. Например:

```php
Event::listen(...);
```

Так как ни один из подходов не является «правильным» по умолчанию, выберите тот, который подходит по масштабу приложения.

### Подписка с приоритетом

Можно указать приоритет третьим аргументом при подписке на события. Слушатели с более высоким приоритетом выполняются первыми, а слушатели с одинаковым приоритетом — в порядке подписки.

```php
// Run first
Event::listen('auth.login', function() { ... }, 10);

// Run second
Event::listen('auth.login', function() { ... }, 5);
```

### Остановка событий

Иногда требуется прекратить дальнейшую обработку события другими слушателями. Для этого верните `false` из обработчика:

```php
Event::listen('auth.login', function($event) {
    // Handle the event

    return false;
});
```

### Подстановочные слушатели

При регистрации слушателя события можно использовать символы `*`, чтобы указать подстановочный слушатель. Такие слушатели сначала получают имя вызванного события, а затем — массив параметров, переданных событию.

Следующий слушатель обрабатывает все события, которые начинаются с `foo.`.

```php
Event::listen('foo.*', function($event, $params) {
    // Handle the event...
});
```

Чтобы определить, какое событие было вызвано, используйте метод `Event::firing`.

```php
Event::listen('foo.*', function($event, $params) {
    if (Event::firing() === 'foo.bar') {
        // ...
    }
});
```

## Вызов событий

Метод `Event::fire` можно использовать в любом месте кода, чтобы сделать логику расширяемой. Это означает, что другие разработчики или даже внутренний код могут «подцепиться» к этой точке и внедрить дополнительную логику. Первый аргумент должен содержать имя события.

```php
Event::fire('myevent');
```

Всегда полезно добавлять к имени события префикс с пространством имён плагина, чтобы избежать конфликтов с другими плагинами.

```php
Event::fire('acme.blog.myevent');
```

Второй аргумент — массив значений, который будет передан слушателю события в качестве аргументов.

```php
Event::fire('acme.blog.myevent', [$arg1, $arg2]);
```

Третий аргумент определяет, должно ли событие останавливаться (halting event), то есть прекращать выполнение при возврате ненулевого значения. По умолчанию этот аргумент равен `false`.

```php
Event::fire('acme.blog.myevent', [...], true);
```

Если событие остановлено, будет возвращено первое полученное значение.

```php
// Single result, event halted
$result = Event::fire('acme.blog.myevent', [...], true);
```

В противном случае будет возвращена коллекция ответов всех слушателей в виде массива.

```php
// Multiple results, all events fired
$results = Event::fire('acme.blog.myevent', [...]);
```

## Передача аргументов по ссылке

При обработке или фильтрации значения, переданного событию, можно добавить префикс `&`, чтобы передать его по ссылке. Это позволяет нескольким слушателям изменять результат и передавать его дальше.

```php
Event::fire('cms.processContent', [&$content]);
```

При подписке на событие аргумент также должен быть объявлен с символом `&` в определении замыкания. В примере ниже к переменной `$content` будет добавлена строка «AB».

```php
Event::listen('cms.processContent', function (&$content) {
    $content = $content . 'A';
});

Event::listen('cms.processContent', function (&$content) {
    $content = $content . 'B';
});
```

### Поставленные в очередь события

Вызов событий можно отложить [совместно с очередями](./queue.md). Метод `Event::queue` добавляет событие в очередь без немедленного запуска.

```php
Event::queue('foo', [$user]);
```

Метод `Event::flush` очищает все поставленные в очередь события.

```php
Event::flush('foo');
```

## Использование классов в качестве слушателей

В некоторых случаях удобнее обрабатывать событие классом, а не замыканием. Классы-слушатели событий разрешаются из [контейнера служб приложения](./application.md), что позволяет использовать полноценное внедрение зависимостей.

### Подписка на отдельные методы

Класс события можно зарегистрировать методом `Event::listen`, как и любой другой слушатель, передав имя класса строкой.

```php
Event::listen('auth.login', LoginHandler::class);
```

По умолчанию будет вызван метод `handle` класса `LoginHandler`:

```php
class LoginHandler
{
    public function handle($data)
    {
        // ...
    }
}
```

Если не требуется использовать метод `handle` по умолчанию, укажите имя метода, который должен быть подписан.

```php
Event::listen('auth.login', [LoginHandler::class, 'onLogin']);
```

### Подписка на весь класс

Подписчики событий — это классы, которые могут подписываться на несколько событий изнутри самого класса. Подписчик должен определить метод `subscribe`, которому будет передан экземпляр диспетчера событий.

```php
class UserEventHandler
{
    /**
     * subscribe регистрирует слушателей для подписчика.
     * @param  Illuminate\Events\Dispatcher  $events
     * @return array
     */
    public function subscribe($events)
    {
        $events->listen('auth.login', [static::class, 'userLogin']);

        $events->listen('auth.logout', [static::class, 'userLogout']);
    }

    /**
     * userLogin обрабатывает события входа пользователя.
     */
    public function userLogin($event)
    {
        // ...
    }

    /**
     * userLogout обрабатывает события выхода пользователя.
     */
    public function userLogout($event)
    {
        // ...
    }
}
```

После определения подписчика его можно зарегистрировать методом `Event::subscribe`.

```php
Event::subscribe(new UserEventHandler);
```

Можно также разрешить подписчика через [контейнер служб приложения](./application.md). Для этого передайте имя класса подписчика методу `subscribe`.

```php
Event::subscribe(UserEventHandler::class);
```

## Трейт эмиттера событий

Иногда требуется привязать события к отдельному экземпляру объекта. Для этого можно использовать альтернативную систему событий, подключив трейт `October\Rain\Support\Traits\Emitter` внутри класса.

```php
class UserManager
{
    use \October\Rain\Support\Traits\Emitter;
}
```

Этот трейт предоставляет метод `bindEvent` для регистрации слушателей.

```php
$manager = new UserManager;
$manager->bindEvent('user.beforeRegister', function($user) {
    // Check if the $user is a spammer
});
```

Метод `fireEvent` используется для вызова событий.

```php
$manager = new UserManager;
$manager->fireEvent('user.beforeRegister', [$user]);
```

Эти события будут происходить только на локальном объекте, а не глобально.
