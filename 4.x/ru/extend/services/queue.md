# Очередь

Очереди позволяют отложить выполнение ресурсоёмкой задачи, например отправку e-mail, на более позднее время, что значительно ускоряет веб-запросы к приложению.

## Конфигурация

Конфигурация очереди хранится в файле `config/queue.php`. В этом файле описаны настройки подключения для каждого драйвера очереди, включая базу данных, [Beanstalkd](https://beanstalkd.github.io), [Amazon SQS](https://aws.amazon.com/sqs/), [Redis](https://redis.io), драйвер null и синхронный драйвер (для локального использования). Драйвер очереди `null` просто отбрасывает задачи, поэтому они никогда не выполняются.

### Требования драйверов

Для перечисленных драйверов очередей требуются следующие зависимости. Их можно установить через менеджер пакетов Composer.

Connection | Package
------------- | -------------
Amazon SQS | `aws/aws-sdk-php ~3.0`
Beanstalkd | `pda/pheanstalk ~4.0`
Redis      | `predis/predis ~1.0` или расширение PHP phpredis

## Базовое использование

Чтобы поместить новую задачу (job) в очередь, используйте метод `Queue::push`.

```php
Queue::push(SendEmail::class, ['message' => $message]);
```

Первый аргумент метода `push` — имя класса, который должен обработать задачу. Второй аргумент — массив данных, передаваемых обработчику. Обработчик задачи может быть определён в файле **app/SendEmail.php** так:

```php
class SendEmail
{
    public function fire($job, $data)
    {
        //
    }
}
```

Единственный обязательный метод — `fire`, который получает экземпляр `Job`, а также массив `data`, переданный в очередь. Если задача должна использовать метод, отличный от `fire`, можно указать этот метод при постановке задачи в очередь:

```php
Queue::push('SendEmail@send', ['message' => $message]);
```

#### Указание имени очереди для задачи

Можно указать очередь/трубу, в которую отправляется задача:

```php
Queue::push('SendEmail@send', ['message' => $message], 'emails');
```

#### Отложенное выполнение задачи

Иногда требуется отложить выполнение задачи. Например, можно поставить задачу, которая отправит клиенту e-mail через 15 минут после регистрации. Это делается методом `Queue::later`:

```php
$date = Carbon::now()->addMinutes(15);

Queue::later($date, 'SendEmail', ['message' => $message]);
```

В этом примере используется библиотека дат [Carbon](https://github.com/briannesbitt/Carbon) для указания задержки. Вместо объекта даты можно передать количество секунд задержки целым числом.

> **Примечание**: сервис Amazon SQS поддерживает задержку не более 900 секунд (15 минут).

#### Очереди и модели

Если задача принимает модель в данных, в очередь будет сериализован только идентификатор модели. Когда задача будет обработана, система очередей автоматически заново извлечёт полный экземпляр модели из базы данных. Это полностью прозрачно для приложения и предотвращает проблемы, связанные с сериализацией целых экземпляров моделей.

#### Удаление обработанной задачи

После обработки задачу нужно удалить из очереди методом `delete` экземпляра `Job`:

```php
public function fire($job, $data)
{
    // Обработка задачи...

    $job->delete();
}
```

#### Возврат задачи обратно в очередь

Чтобы вернуть задачу обратно в очередь, используйте метод `release`:

```php
public function fire($job, $data)
{
    // Обработка задачи...

    $job->release();
}
```

Можно указать количество секунд ожидания перед повторным добавлением задачи:

```php
$job->release(5);
```

#### Проверка числа попыток запуска

Если при обработке задачи возникает исключение, она автоматически возвращается в очередь. Проверить количество попыток обработки можно методом `attempts`:

```php
if ($job->attempts() > 3) {
    //
}
```

#### Доступ к идентификатору задачи

Можно получить идентификатор задачи:

```php
$job->getJobId();
```

## Постановка в очередь замыканий

В очередь можно помещать и замыкания. Это удобно для быстрых, простых задач, которые нужно поставить в очередь.

#### Добавление замыкания в очередь

```php
Queue::push(function($job) use ($id) {
    Account::delete($id);

    $job->delete();
});
```

::: tip
Вместо передачи объектов в замыкание очереди через директиву `use` лучше передавать первичные ключи и повторно получать связанные модели внутри задачи очереди. Это помогает избежать неожиданного поведения сериализации.
:::

## Запуск обработчика очереди

October CMS включает несколько консольных команд для обработки задач очереди. Чтобы обрабатывать новые задачи по мере их поступления, выполните команду `queue:work`:

```bash
php artisan queue:work
```

После запуска процесс будет работать, пока его не остановят вручную. Чтобы гарантировать непрерывную работу обработчика, используйте монитор процессов, например [Supervisor](#oc-supervisor-configuration).

Процессы обработчиков очередей хранят загруженное состояние приложения в памяти. Они не увидят изменения в коде после запуска. При выкладке изменений перезапускайте обработчики очередей.

#### Обработка одной задачи

Чтобы обработать только первую задачу в очереди, используйте опцию `--once`:

```bash
php artisan queue:work --once
```

#### Выбор соединения и очереди

Можно указать, какое соединение очереди должен использовать обработчик:

```bash
php artisan queue:work --once connection
```

Чтобы задать приоритеты очередей, передайте в команду `work` список соединений через запятую:

```bash
php artisan queue:work --once --queue=high,low
```

В этом примере задачи из очереди `high` всегда обрабатываются прежде, чем задачи из очереди `low`.

#### Параметр времени ожидания задачи

Можно задать длительность (в секундах), в течение которой задача может выполняться:

```bash
php artisan queue:work --once --timeout=60
```

#### Интервал опроса очереди

Также можно указать количество секунд ожидания перед опросом новых задач:

```bash
php artisan queue:work --once --sleep=5
```

Учтите, что обработчик «засыпает» только если очередь пуста. При наличии задач очередь обрабатывается без пауз.

## Демон-обработчик очереди

По умолчанию `queue:work` обрабатывает задачи, не перезапуская фреймворк. Это существенно снижает нагрузку на CPU по сравнению с `queue:work --once`, но добавляет сложность, поскольку при выкладке нужно освобождать очереди от выполняемых задач.

Чтобы запустить обработчик очереди в режиме демона, просто опустите флаг `--once`:

```bash
php artisan queue:work connection

php artisan queue:work connection --sleep=3

php artisan queue:work connection --sleep=3 --tries=3
```

Просмотреть все доступные опции можно командой `php artisan help queue:work`.

### Деплой с демон-обработчиками очередей

Проще всего выкладывать приложение с демон-обработчиками, переведя его в режим обслуживания в начале выкладки. Это можно сделать в разделе настроек бэкенда. Пока приложение в режиме обслуживания, October не принимает новые задачи из очереди, но продолжает обрабатывать существующие.

Самый простой способ перезапустить обработчики — добавить в скрипт выкладки следующую команду:

```bash
php artisan queue:restart
```

Эта команда указывает всем обработчикам очередей перезапуститься после завершения текущей задачи.

::: tip
Команда использует систему кеширования для планирования перезапуска. По умолчанию APCu не работает для CLI-команд. Если используется APCu, добавьте `apc.enable_cli=1` в конфигурацию APCu.
:::

### Разработка для демон-обработчиков очередей

Демон-обработчики очередей не перезапускают платформу перед обработкой каждой задачи. Поэтому освобождайте ресурсоёмные ресурсы до завершения задачи. Например, при обработке изображений через библиотеку GD освободите память вызовом `imagedestroy`.

Аналогично соединение с базой данных может быть разорвано при длительной работе демона. Используйте метод `Db::reconnect`, чтобы гарантировать новое соединение.

## Конфигурация Supervisor

### Установка Supervisor

Supervisor — монитор процессов для Linux, который автоматически перезапускает процесс `queue:work`, если он завершится с ошибкой. В Ubuntu Supervisor устанавливается командой:

```bash
sudo apt-get install supervisor
```

### Настройка Supervisor

Файлы конфигурации Supervisor обычно находятся в каталоге `/etc/supervisor/conf.d`. В этом каталоге можно создать любое количество конфигурационных файлов, описывающих, как Supervisor должен отслеживать процессы. Например, создадим файл `october-worker.conf`, который запускает и отслеживает процесс `queue:work`.

```ini
[program:october-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/october/artisan queue:work --sleep=3 --tries=3
autostart=true
autorestart=true
user=october
numprocs=8
redirect_stderr=true
stdout_logfile=/path/to/october/worker.log
```

В этом примере директива `numprocs` заставляет Supervisor запускать и отслеживать восемь процессов `queue:work`, автоматически перезапуская их при сбое. Разумеется, часть команды `queue:work` следует изменить в соответствии с нужным соединением очереди. Директиву `user` нужно заменить на имя пользователя, имеющего права на запуск команды.

### Запуск Supervisor

После создания конфигурационного файла обновите конфигурацию Supervisor и запустите процессы следующими командами:

```bash
sudo supervisorctl reread

sudo supervisorctl update

sudo supervisorctl start october-worker:*
```

Дополнительные сведения доступны в [документации Supervisor](http://supervisord.org/index.html).

## Сбойные задачи

Иногда задачи в очереди завершаются с ошибкой. Ничего страшного, такое бывает. Есть удобный способ задать максимальное количество попыток выполнения задачи. После превышения лимита задача будет записана в таблицу `failed_jobs`. Имя таблицы настраивается в конфигурационном файле `config/queue.php`.

Максимальное количество попыток можно указать с помощью переключателя `--tries` команды `queue:work`:

```bash
php artisan queue:work connection-name --tries=3
```

Чтобы зарегистрировать обработчик события при сбое задачи очереди, используйте метод `Queue::failing`. Это хорошая возможность уведомить команду по e-mail или через сторонний сервис.

```php
Queue::failing(function($connection, $job, $data) {
    //
});
```

Также можно определить метод `failed` непосредственно в классе задачи, чтобы выполнять специфичные действия при сбое:

```php
public function failed($data)
{
    // Вызывается при сбое задачи...
}
```

Исходный массив `data` автоматически передаётся в метод `failed`.

### Повторный запуск сбойных задач

Чтобы просмотреть все сбойные задачи, используйте Artisan-команду `queue:failed`:

```bash
php artisan queue:failed
```

Команда `queue:failed` выводит идентификатор задачи, соединение, очередь и время сбоя. Идентификатор задачи можно использовать для повторного запуска. Например, чтобы повторно запустить задачу с идентификатором 5, выполните команду:

```bash
php artisan queue:retry 5
```

Чтобы удалить сбойную задачу, выполните команду `queue:forget`:

```bash
php artisan queue:forget 5
```

Чтобы удалить все сбойные задачи, выполните команду `queue:flush`:

```bash
php artisan queue:flush
```
