# Контроллеры

Бэкенд October CMS реализует паттерн Model-View-Controller (MVC). В этой статье описано, как разрабатывать контроллеры бэкенда и настраивать поведения (behavior) контроллера.

Каждый контроллер представлен PHP-скриптом в подкаталоге **/controllers** каталога плагина. Представления контроллера — это файлы `.php`, расположенные в каталоге представлений контроллера. Имя каталога представлений совпадает с именем класса контроллера, записанным строчными буквами. В каталоге представлений также можно размещать файлы конфигурации контроллера. Пример структуры каталога контроллера:

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── `controllers`
|           |   ├── users  _← Каталог представлений_
|           |   |   ├── config_form.yaml  _← Файл конфигурации_
|           |   |   ├── _partial.php  _← Частичное представление_
|           |   |   └── index.php  _← Файл представления_
|           |   └── Users.php  _← Класс контроллера_
|           └── Plugin.php
:::

:::tip
Практический пример работы с контроллерами бэкенда приведён в [серии уроков Beyond Behaviors](https://octobercms.com/support/article/ob-19).
:::

### Определение класса

Команда `create:controller` создаёт контроллер, файлы конфигурации и представлений. Первый аргумент задаёт автора и плагин. Второй аргумент указывает имя класса контроллера.

```bash
php artisan create:controller Acme.Blog Posts
```

Классы контроллеров должны наследовать `Backend\Classes\Controller`. Как и другие классы плагина, контроллеры должны принадлежать [пространству имён плагина](../system/plugins.md). Самый простой пример контроллера внутри плагина выглядит так.

```php
namespace Acme\Blog\Controllers;

class Posts extends \Backend\Classes\Controller
{
    public function index()    // ← Метод действия
    {

    }
}
```

Обычно каждый контроллер реализует работу с одним типом данных — например, с записями блога или категориями. Все описанные ниже поведения бэкенда предполагают именно такую структуру.

### Свойства контроллера

Базовый класс контроллера бэкенда определяет ряд свойств для настройки внешнего вида страницы и управления её безопасностью:

Свойство | Описание
------------- | -------------
**$fatalError** | Позволяет сохранить критическое исключение, возникшее в методе действия, чтобы отобразить его в представлении.
**$user** | Содержит ссылку на объект пользователя бэкенда.
**$suppressView** | Позволяет отключить отображение представления. Можно изменить в методе действия или конструкторе контроллера.
**$params** | Массив параметров из маршрута.
**$action** | Имя метода действия, выполняемого в текущем запросе.
**$publicActions** | Массив действий, доступных без аутентификации в бэкенде. Можно переопределить в определении класса.
**$requiredPermissions** | Разрешения, необходимые для просмотра страницы. Можно задать в определении класса или конструкторе контроллера. Подробнее см. [Users & Permissions](../backend/users.md).
**$pageTitle** | Задаёт заголовок страницы. Можно назначить в методе действия.
**$bodyClass** | Значение класса для тега `<body>` для кастомизации макета. Можно задать в конструкторе или методе действия.
**$guarded** | Методы контроллера, которые нельзя вызывать как действия. Можно расширить в конструкторе контроллера.
**$layout** | Указывает пользовательский макет для [представлений контроллера](../system/views.md).

## Логика инициализации

Контроллеры могут выполнять инициализацию в стандартном методе `__construct`.

::: warning
Логика в конструкторе не защищена и не должна обрабатывать чувствительные данные.
```php
public function __construct()
{
    parent::__construct();
}
```
:::

Метод `beforeDisplay` вызывается после проверки разрешений, и основную логику следует размещать здесь. В частности, инициализировать виджеты и другие общие компоненты.

```php
public function beforeDisplay()
{
    // Initialize widgets, handle file uploads, etc.
}
```

## Действия, представления и маршрутизация

Публичные методы контроллера — **действия** — связаны с **файлами представлений**, которые отображают страницу, соответствующую действию. Представления бэкенда используют синтаксис PHP. Пример содержимого представления **index.php**, соответствующего методу действия `index`.

```html
<h1>Hello World</h1>
```

URL этой страницы формируется из имени автора, названия плагина, контроллера и действия.

```text
admin/[author name]/[plugin name]/[controller name]/[action name]
```

Например, класс, представленный в начале статьи, доступен по следующему URL.

```text
https://example.tld/admin/acme/blog/users/index
```

Если [плагин зарегистрирован](./plugins.md) с **подсказкой** (hint) в методе `pluginDetails`, становится доступна сокращённая структура URL, полезная для скрытия имени автора в адресах.

```text
admin/[plugin hint]/[controller name]/[action name]
```

## Передача данных в представления

Используйте свойство `$vars` контроллера, чтобы напрямую передавать данные в представление:

```php
$this->vars['myVariable'] = 'value';
```

Переменные, переданные через `$vars`, становятся доступны в представлении напрямую:

```php
<p>The variable value is <?= $myVariable ?></p>
```

## Настройка контекста навигации

Плагины могут регистрировать пункты и подпункты меню бэкенда в [файле регистрации плагина](../backend/navigation.md). Контекст навигации определяет, какие меню и подменю активны на текущей странице бэкенда. Контекст задаётся классом `BackendMenu`:

```php
BackendMenu::setContext('Acme.Blog', 'blog', 'categories');
```

Первый параметр задаёт имя автора и плагина. Второй — код меню. Необязательный третий параметр указывает код подпункта. Обычно `BackendMenu::setContext` вызывают в конструкторе контроллера.

```php
namespace Acme\Blog\Controllers;

class Categories extends \Backend\Classes\Controller {

public function __construct()
{
    parent::__construct();

    BackendMenu::setContext('Acme.Blog', 'blog', 'categories');
}
```

Заголовок страницы бэкенда можно задать свойством `$pageTitle` класса контроллера (учитывайте, что поведения формы и списка делают это автоматически):

```php
$this->pageTitle = 'Blog Categories';
```

## Переопределение ответа

В контроллерах бэкенда можно переопределять ответы, чтобы изменять реакцию на HTTP-запрос. Например, можно задать заголовок ответа для отдельных действий или перенаправить пользователя, если не выполнены определённые условия.

Переопределение ответа особенно полезно при расширении других контроллеров. Однако эти методы можно вызывать и локально.

```php
\Author\Plugin\Controllers\SomeController::extend(function($controller) {
    $controller->setResponseHeader('Test-Header', 'Test');
});
```

Если требуется проверить действие или параметры маршрута, используйте методы `getAction` и `getParams` контроллера.

```php
Author\Plugin\Controllers\SomeController::extend(function($controller) {
    if ($controller->getAction() === 'index') {
        // Only do it for the index action
    }

    if ($controller->getParams()[0] ?? null) {
        // Only if first parameter exists
    }
});
```

Чтобы добавить заголовок в ответ, вызовите `setResponseHeader`.

```php
$this->setResponseHeader('Test-Header', 'Test');
```

Чтобы изменить код состояния ответа, используйте `setStatusCode`.

```php
$this->setStatusCode(404);
```

Чтобы полностью заменить ответ, вызовите `setResponse`. Этот метод принудительно вернёт указанный ответ независимо от дальнейшего жизненного цикла страницы.

```php
$this->setResponse('Page Not Found');
```

Методу можно передать и объект `Response`.

```php
$this->setResponse(Response::make(...));
```

Дополнительную информацию о создании ответов см. в статье [Представления и ответы](../services/response-view.md).
