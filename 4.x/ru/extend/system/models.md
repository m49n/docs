# Модели

October CMS предоставляет удобную реализацию Active Record для работы с базой данных на основе [Eloquent от Laravel](http://laravel.com/docs/eloquent). Каждой таблице базы данных соответствует «модель», с помощью которой выполняются операции с этой таблицей. Модели позволяют извлекать данные и добавлять новые записи.

Классы моделей находятся в подкаталоге **models** каталога плагина. Пример структуры каталога модели.

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── `models`
|           |   ├── post  _← Каталог конфигурации_
|           |   |   ├── fields.yaml  _← Файл конфигурации_
|           |   |   └── columns.yaml  _← Файл конфигурации_
|           |   └── Post.php  _← Класс модели_
|           └── Plugin.php
:::

Каталог конфигурации модели может содержать [определения полей форм](../../element/form-fields.md). Имя каталога конфигурации совпадает с именем класса модели, записанным строчными буквами.

## Определение моделей

Команда `create:model` создаёт файлы, необходимые для новой модели. Первый аргумент задаёт автора и плагин. Второй аргумент указывает имя класса модели.

```bash
php artisan create:model Acme.Blog Post
```

В большинстве случаев для каждой таблицы базы данных следует создавать отдельный класс модели. Все классы моделей должны наследовать `Model`. Самый простой пример модели внутри плагина выглядит так.

```php
namespace Acme\Blog\Models;

use Model;

class Post extends Model
{
    protected $table = 'acme_blog_posts';
}
```

За соответствующую таблицу отвечает защищённое свойство `$table`. Имя таблицы образуется в `snake_case` из автора, плагина и множественного числа типа записи.

### Поддерживаемые свойства

Помимо свойств, предоставляемых [тейтами модели](traits.md), модели поддерживают стандартные свойства. Например:

```php
class User extends Model
{
    protected $primaryKey = 'id';

    public $exists = false;

    protected $dates = ['last_seen_at'];

    public $timestamps = true;

    protected $jsonable = ['permissions'];

    protected $guarded = ['*'];
}
```

Свойство | Описание
------------- | -------------
**$primaryKey** | Имя первичного ключа, используемого для идентификации модели.
**$incrementing** | Булево значение; если `false`, первичный ключ не является автоинкрементируемым целым числом.
**$exists** | Булево значение; если `true`, указывает, что модель существует.
**$dates** | Значения после извлечения приводятся к экземплярам Carbon/DateTime.
**$timestamps** | Булево значение; если `true`, автоматически заполняет поля created_at и updated_at.
**$jsonable** | Значения сериализуются в JSON перед сохранением и преобразуются в массивы после извлечения.
**$fillable** | Поля, доступные для массового заполнения.
**$guarded** | Поля, защищённые от массового заполнения.
**$visible** | Поля, отображаемые при [сериализации модели](../database/serialization.md).
**$hidden** | Поля, скрываемые при [сериализации модели](../database/serialization.md).
**$connection** | Строка с [именем подключения](../../setup/database-config.md), используемого моделью по умолчанию.

#### Первичный ключ

По умолчанию считается, что в таблице есть столбец первичного ключа `id`. Чтобы изменить это, переопределите свойство `$primaryKey`.

```php
class Post extends Model
{
    protected $primaryKey = 'id';
}
```

#### Автоинкремент

По умолчанию первичный ключ считается автоинкрементируемым целым числом, поэтому значение приводится к целому автоматически. Если требуется неинкрементируемый или нечисловой ключ, установите публичное свойство `$incrementing` в `false`.

```php
class Message extends Model
{
    public $incrementing = false;
}
```

#### Метки времени

По умолчанию модель ожидает наличие столбцов `created_at` и `updated_at`. Если не нужно управлять ими автоматически, установите свойство `$timestamps` в `false`.

```php
class Post extends Model
{
    public $timestamps = false;
}
```

Чтобы изменить формат меток времени, задайте свойство `$dateFormat`. Оно определяет, как даты сохраняются в базе данных и в каком формате сериализуются в массив или JSON.

```php
class Post extends Model
{
    protected $dateFormat = 'U';
}
```

#### Значения, сохраняемые как JSON

Если имена атрибутов перечислены в свойстве `$jsonable`, значения будут сериализованы и десериализованы как JSON.

```php
class Post extends Model
{
    protected $jsonable = ['data'];
}
```

## События модели

Модели генерируют ряд событий, позволяя подключаться к различным этапам жизненного цикла. События позволяют выполнять код при каждом сохранении или обновлении экземпляра модели. События определяются переопределением специальных методов; доступны следующие методы:

Событие | Описание
------------- | -------------
**beforeCreate** | Перед сохранением модели при первом создании.
**afterCreate** | После сохранения модели при первом создании.
**beforeSave** | Перед сохранением модели (создание или обновление).
**afterSave** | После сохранения модели (создание или обновление).
**beforeValidate** | Перед валидацией переданных данных модели.
**afterValidate** | После валидации переданных данных модели.
**beforeUpdate** | Перед сохранением существующей модели.
**afterUpdate** | После сохранения существующей модели.
**beforeDelete** | Перед удалением существующей модели.
**afterDelete** | После удаления существующей модели.
**beforeRestore** | Перед восстановлением мягко удалённой модели.
**afterRestore** | После восстановления мягко удалённой модели.
**beforeFetch** | Перед заполнением существующей модели.
**afterFetch** | После заполнения существующей модели.

Пример использования события:

```php
public function beforeCreate()
{
    $this->slug = Str::slug($this->name);
}
```

### Базовое использование

При первом сохранении новой модели срабатывают события `beforeCreate` и `afterCreate`. Если модель уже существует в базе и вызывается метод `save`, сработают события `beforeUpdate` / `afterUpdate`. В обоих случаях вызываются также события `beforeSave` / `afterSave`.

Например, определим обработчик, который заполняет атрибут `slug` при первом создании модели.

```php
public function beforeCreate()
{
    $this->slug = Str::slug($this->name);
}
```

Возврат `false` из события отменяет операцию `save` / `update`.

```php
public function beforeCreate()
{
    if (!$user->isValid()) {
        return false;
    }
}
```

Доступ к старым значениям возможен через свойство `original`. Например:

```php
public function afterUpdate()
{
    if ($this->title !== $this->original['title']) {
        // Title has changed
    }
}
```

Отношения, созданные с помощью [отложенных привязок](../database/relations.md) (например, вложения файлов), могут быть недоступны внутри событий модели. Чтобы получить к ним доступ заранее, используйте метод запроса `withDeferred` для связи.

```php
public function beforeCreate()
{
    $avatar = $this->avatar()->withDeferred()->first();

    $gallery = $this->gallery()->withDeferred()->get();
}
```

Для подключения к [локальным событиям](../services/event.md) конкретного экземпляра модели используйте метод `bindEvent`. Имя события должно совпадать с именем переопределяемого метода с префиксом `model.`.

```php
$flight = new Flight;
$flight->bindEvent('model.beforeCreate', function() use ($model) {
    $model->slug = Str::slug($model->name);
});
```

## Расширение моделей

Поскольку модели [поддерживают поведения](./behaviors.md), их можно расширять статическим методом `extend`. Метод принимает замыкание и передаёт в него объект модели.

Внутри замыкания можно добавлять связи. В примере ниже модель `User` расширяется связью профиля (hasOne), которая указывает на модель `Profile`.

```php
User::extend(function($model) {
    $model->hasOne['profile'] = [Profile::class, 'key' => 'user_id'];
});
```

Таким же образом можно подключаться к локальным событиям: следующий код слушает событие `model.beforeSave`.

```php
User::extend(function($model) {
    $model->bindEvent('model.beforeSave', function() use ($model) {
        // ...
    });
});
```

Дополнительно доступны методы для расширения защищённых свойств модели.

```php
User::extend(function($model) {
    // Добавление приведения типов
    $model->addCasts([
        'some_extended_field' => 'int',
    ]);

    // Добавление атрибута даты
    $model->addDateAttribute('updated_at');

    // Добавление полей fillable или jsonable
    $model->addFillable('first_name');
    $model->addJsonable('some_data');
});
```

Обычно лучше всего размещать код в методе `boot` [файла регистрации плагина](../extending.md), чтобы он выполнялся при каждом запросе и расширение модели было доступно везде.
