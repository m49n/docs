# Рендеринг представлений

Файлы представлений располагаются в каталоге с именем, совпадающим с именем контроллера.

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── controllers
|           |   ├── users  _← Каталог представлений_
|           |   |   ├── `_partial.php`  _← Частичное представление_
|           |   |   └── `index.php`  _← Файл представления_
|           |   └── Users.php  _← Класс контроллера_
|           └── Plugin.php
:::

## Частичные представления

Частичные представления бэкенда — это файлы с расширением **php**, расположенные в [каталоге представлений контроллера](./controllers.md). Их имена должны начинаться с символа подчёркивания: **_partial.php**. Частичные представления можно рендерить из страницы бэкенда или другого частичного представления. Используйте метод контроллера `makePartial`, который принимает имя частичного представления и необязательный массив переменных. Пример:

```php
<?= $this->makePartial('sidebar', ['showHeader' => true]) ?>
```

### Подсказки (hints)

В бэкенде можно выводить информационные панели (подсказки), которые пользователь может скрывать. Первый параметр — уникальный ключ, позволяющий запомнить, было ли скрыто подсказку. Второй параметр — ссылка на частичное представление. Третьим параметром передаётся массив дополнительных переменных и свойств подсказки.

```php
<?= $this->makeHintPartial('my_hint_key', 'my_hint_partial', ['foo' => 'bar']) ?>
```

Чтобы запретить скрытие подсказки, передайте `null` вместо ключа — такая подсказка всегда отображается:

```php
<?= $this->makeHintPartial(null, 'my_hint_partial') ?>
```

Доступные свойства подсказки:

Property | Description
------------- | -------------
**type** | Цвет подсказки. Допустимые значения: danger, info, success, warning. По умолчанию info.
**title** | Заголовок подсказки.
**subtitle** | Вторая строка заголовка.
**icon** | Значок в заголовке.

### Проверка скрытого состояния подсказок

Если используются подсказки, можно проверить, скрыта ли подсказка пользователем. Для этого используйте метод `isBackendHintHidden`, передав уникальный ключ, использованный в `makeHintPartial`. Метод возвращает true, если подсказка скрыта, и false в противном случае:

```php
<?php if ($this->isBackendHintHidden('my_hint_key')): ?>
    <!-- Do something when the hint is hidden -->
<?php endif ?>
```

## Макеты и дочерние макеты

Макеты бэкенда располагаются в необязательном каталоге **layouts/** плагина. Пользовательский макет задаётся свойством `$layout` контроллера. По умолчанию используется системный макет `default`.

```php
/**
 * @var string layout to use for the view.
 */
public $layout = 'mycustomlayout';
```

В макете можно задать дополнительные CSS-классы для тега BODY через свойство `$bodyClass` контроллера.

```php
/**
 * @var string bodyClass (CSS) to add to the layout.
 */
public $bodyClass = 'compact-container';
```

Для макета по умолчанию доступны следующие классы:

- **compact-container** — убирает отступы со всех сторон.
- **slim-container** — убирает боковые отступы.
- **breadcrumb-flush** — выравнивает хлебные крошки по элементу ниже.

### Макет формы с боковой панелью

Макеты можно использовать подобно частичным представлениям, как «глобальные частичные шаблоны». Системный пример — `form-with-sidebar`, демонстрирующий структуру дочернего макета.

Перед использованием этого макета убедитесь, что контроллер устанавливает класс `compact-container` для тега BODY (в конструкторе или методе действия).

```php
$this->bodyClass = 'compact-container';
```

Макет использует два плейсхолдера: основную область **form-contents** и вспомогательную боковую панель **form-sidebar**. Пример:

```php
<!-- Primary content -->
<?php Block::put('form-contents') ?>
    Main content
<?php Block::endPut() ?>

<!-- Complimentary sidebar -->
<?php Block::put('form-sidebar') ?>
    Side content
<?php Block::endPut() ?>

<!-- Layout execution -->
<?php Block::put('body') ?>
    <?= Form::open(['class'=>'layout stretch']) ?>
        <?= $this->makeLayout('form-with-sidebar') ?>
    <?= Form::close() ?>
<?php Block::endPut() ?>
```

В последнем блоке макет выполняется путём переопределения плейсхолдера **body**, который используется всеми макетами бэкенда. Код оборачивает содержимое в тег `<form />` и рендерит дочерний макет **form-with-sidebar**, расположенный в **modules/backend/layouts/form-with-sidebar.php**.

## Расширение макета

Метод `fireViewEvent` используется в разных местах для [расширения бэкенда](../extending.md). Событие `backend.layout.extendHead` позволяет дополнить элемент `<head>` макета. Возвращаемое значение должно содержать вставляемую разметку. В примере подключается JavaScript-файл на всех страницах бэкенда.

```php
Event::listen('backend.layout.extendHead', function ($controller) {
    return '<script src="/app/assets/js/myscript.js"></script>';
});
```

В обработчик события первым аргументом передаётся контроллер, что позволяет таргетировать конкретные контроллеры. В следующем примере добавляются CSS-стили только для контроллера Tailor.

```php
Event::listen('backend.layout.extendHead', function ($controller) {
    if ($controller instanceof \Tailor\Controllers\Entries) {
        return '<styles> /* ... */ </styles>';
    }
});
```
