# Доступные исключения

### Application Exception

Класс `October\Rain\Exception\ApplicationException` (псевдоним `ApplicationException`) — самый распространённый тип исключений, который используется, когда нарушено простое условие приложения.

```php
throw new ApplicationException('You must be logged in to do that!');
```

Сообщение об ошибке будет упрощено и никогда не содержит конфиденциальных данных, таких как имя PHP-файла и номер строки.

### System Exception

Класс `October\Rain\Exception\SystemException` (псевдоним `SystemException`) применяется для ошибок, критичных для работы системы, и всегда протоколируется.

```php
throw new SystemException('Unable to contact the mail server API');
```

При выбросе такого исключения отображается подробное сообщение с указанием файла и строки, где произошла ошибка.

### Not Found Exception

Класс `October\Rain\Exception\NotFoundException` (псевдоним `NotFoundException`) используется, когда возникает ошибка из-за отсутствующей записи.

```php
throw new NotFoundException('Record not found');
```

При выбросе исключения стандартный ответ изменяется: отображается ближайшая страница «не найдено» с кодом состояния 404.

### Validation Exception

Класс `October\Rain\Exception\ValidationException` (псевдоним `ValidationException`) применяется для ошибок, связанных непосредственно с отправкой формы и некорректным полем. В сообщение нужно передать массив с полями и текстами ошибок.

```php
throw new ValidationException(['username' => 'Sorry that username is already taken!']);
```

Можно также передать экземпляр [сервиса валидации](../services/validation.md).

```php
$validation = Validator::make(...);

if ($validation->fails()) {
    throw new ValidationException($validation);
}
```

При выбросе этого исключения [AJAX-фреймворк](./ajax.md) предоставит информацию в удобном формате и сфокусирует первое некорректное поле.

### AJAX Exception

Класс `October\Rain\Exception\AjaxException` (псевдоним `AjaxException`) считается «умной ошибкой» и возвращает HTTP-код 406. Это позволяет передавать содержимое ответа так же, как при успешном выполнении.

```php
throw new AjaxException(['#flashMessages' => $this->renderPartial(...)]);
```

При выбросе исключения [AJAX-фреймворк](./ajax.md) выполнит стандартный процесс обработки ошибок и обновит указанные частичные представления.

## Обработка исключений

Все исключения обрабатывает класс `October\Rain\Foundation\Exception\Handler`. Он содержит два метода — `report` и `render`, которые определяют, нужно ли протоколировать ошибку и какой ответ вернуть.

При необходимости можно определить собственные обработчики с помощью метода `App::error`. Обработчики вызываются по типу исключения, указанному в сигнатуре. Например, можно создать обработчик только для экземпляров `RuntimeException`:

```php
App::error(function(RuntimeException $exception) {
    // Handle the exception...
});
```

Если обработчик исключения возвращает ответ, он будет отправлен в браузер, и остальные обработчики вызваны не будут.

```php
App::error(function(InvalidUserException $exception) {
    return 'Sorry! Something is wrong with this account!';
});
```

Чтобы отлавливать фатальные ошибки PHP, проверьте тип исключения `Error`:

```php
App::error(function(Error $exception) {
    //
});
```

Если определено несколько обработчиков, располагайте их от наиболее общего к наиболее конкретному. Например, обработчик для всех исключений типа `Exception` следует объявлять перед обработчиком для пользовательского типа `SystemException`.

### Где размещать обработчики ошибок

Регистрация обработчиков ошибок относится к этапу начальной загрузки. Иными словами, они подготавливают приложение к обработке запросов и должны выполняться до вызова маршрута или контроллера. Наиболее распространённое место — метод `boot` [файла регистрации плагина](../extending.md). Альтернативно плагин может содержать файл **init.php** в каталоге плагина, куда тоже можно поместить регистрацию обработчиков.

## HTTP-исключения

Некоторые исключения описывают HTTP-коды ошибок сервера. Например, это может быть «страница не найдена» (404), «неавторизовано» (401) или даже сгенерированная разработчиком ошибка 500. Чтобы вернуть такой ответ из любой точки приложения, используйте следующий код.

```php
App::abort(404);
```

Метод `abort` немедленно возбуждает исключение, которое будет отрисовано обработчиком исключений. Дополнительно можно передать текст ответа.

```php
App::abort(403, 'Unauthorized action.');
```

Этот метод можно вызывать в любой момент жизненного цикла запроса. Также доступен соответствующий [фильтр Twig для прерывания запроса](../../markup/function/abort.md).

### Пользовательская страница ошибки

По умолчанию ошибки отображаются в подробном виде: с содержимым файла, номером строки и трассировкой стека. Чтобы показать пользовательскую страницу ошибки, установите значение `debug` в **false** в файле `config/app.php` и создайте страницу с URL `/error`.
