# Планировщик задач

::: aside
См. [руководство по установке](../../setup/installation.md) для настройки задания планировщика.
:::

Ранее разработчики создавали отдельную запись Cron для каждой задачи. Это неудобно: расписание не хранится в системе контроля версий, а для добавления записей нужно подключаться к серверу по SSH. Планировщик команд позволяет выразительно описать расписание прямо в приложении, и на сервере требуется всего одна запись Cron.

<a id="oc-defining-schedules"></a>
## Определение расписаний

Все задачи планировщика объявляются в методе `registerSchedule`, переопределённом в [регистрационном файле плагина](../extending.md). Метод получает аргумент `$schedule` и используется для определения команд и их частоты.

Рассмотрим пример: запланируем выполнение `Closure` каждый день в полночь. Внутри `Closure` очистим таблицу в базе данных.

```php
class Plugin extends PluginBase
{
    // ...

    public function registerSchedule($schedule)
    {
        $schedule->call(function () {
            Db::table('recent_users')->delete();
        })->daily();
    }
}
```

Помимо `Closure`, можно планировать [консольные команды](../console-commands.md) и команды операционной системы. Например, с помощью метода `command`:

```php
$schedule->command('cache:clear')->daily();
```

Команда `exec` выполняет системную команду:

```php
$schedule->exec('node /home/acme/script.js')->daily();
```

### Частота расписаний

Методы для задания расписания:

Method  | Description
------------- | -------------
`->cron('* * * * *');`  |  Выполнить задачу по произвольному расписанию Cron
`->everyMinute();`  |  Выполнять задачу каждую минуту
`->everyFiveMinutes();`  |  Выполнять задачу каждые пять минут
`->everyTenMinutes();`  |  Выполнять задачу каждые десять минут
`->everyThirtyMinutes();`  |  Выполнять задачу каждые тридцать минут
`->hourly();`  |  Выполнять задачу каждый час
`->daily();`  |  Выполнять задачу ежедневно в полночь
`->dailyAt('13:00');`  |  Выполнять задачу ежедневно в 13:00
`->twiceDaily(1, 13);`  |  Выполнять задачу ежедневно в 1:00 и 13:00
`->weekly();`  |  Выполнять задачу каждую неделю
`->monthly();`  |  Выполнять задачу каждый месяц

Методы можно комбинировать с дополнительными ограничениями, чтобы запускать задачи только в определённые дни недели. Например, запустить команду каждую неделю по понедельникам:

```php
$schedule->call(function () {
    // Runs once a week on Monday at 13:00...
})->weekly()->mondays()->at('13:00');
```

Дополнительные ограничения расписания:

Method  | Description
------------- | -------------
`->weekdays();`  |  Ограничить выполнение будними днями
`->sundays();`  |  Ограничить выполнение воскресеньем
`->mondays();`  |  Ограничить выполнение понедельником
`->tuesdays();`  |  Ограничить выполнение вторником
`->wednesdays();`  |  Ограничить выполнение средой
`->thursdays();`  |  Ограничить выполнение четвергом
`->fridays();`  |  Ограничить выполнение пятницей
`->saturdays();`  |  Ограничить выполнение субботой
`->when(Closure);`  |  Ограничить выполнение условием

#### Условные ограничения

Метод `when` ограничивает выполнение задачи результатом проверки. Если переданное `Closure` возвращает `true`, задача выполнится, если другие ограничения не запрещают запуск.

```php
$schedule->command('emails:send')->daily()->when(function () {
    return true;
});
```

### Предотвращение наложения задач

По умолчанию запланированные задачи выполняются даже тогда, когда предыдущий экземпляр ещё не завершился. Чтобы избежать этого, используйте `withoutOverlapping`.

```php
$schedule->command('emails:send')->withoutOverlapping();
```

В этом примере консольная команда `emails:send` будет запускаться каждую минуту, только если уже не выполняется. Метод `withoutOverlapping` полезен для задач с непредсказуемым временем выполнения.

## Вывод задач

Планировщик предоставляет удобные методы для работы с выводом задач. Метод `sendOutputTo` направляет вывод в файл для последующего анализа.

```php
$schedule->command('emails:send')
    ->daily()
    ->sendOutputTo($filePath);
```

Метод `emailOutputTo` отправляет вывод на указанный адрес электронной почты. Перед этим нужно записать вывод в файл через `sendOutputTo`. Также настройте [почтовые сервисы](../../setup/mail-config.md).

```php
$schedule->command('foo')
    ->daily()
    ->sendOutputTo($filePath)
    ->emailOutputTo('foo@example.tld');
```

::: tip
Методы `emailOutputTo` и `sendOutputTo` применимы только к `command` и не поддерживаются для `call`.
:::

## Хуки задач

С помощью методов `before` и `after` можно выполнить код до и после завершения задачи.

```php
$schedule->command('emails:send')
    ->daily()
    ->before(function () {
        // Task is about to start...
    })
    ->after(function () {
        // Task is complete...
    });
```

#### Пинг URL-адресов

Методы `pingBefore` и `thenPing` позволяют автоматически отправлять запрос по указанному URL до или после выполнения задачи. Это полезно для уведомления внешних сервисов о запуске или завершении задачи.

```php
$schedule->command('emails:send')
    ->daily()
    ->pingBefore($url)
    ->thenPing($url);
```
